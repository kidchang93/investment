# DESIGN

## 설계 원칙

1. **경계에서 정규화(Anti-Corruption Layer).** KIS 원본 스펙(약어 필드, TR_ID, 프레임 포맷)은 `backend/src/kis/`에 격리한다. 바깥은 `@invest/shared`의 명시적 타입만 안다. → KIS 스펙이 바뀌어도 파장이 `kis/`에 갇힌다.
2. **타입 우선(Type-first) 계약.** 백엔드↔프론트의 계약은 `shared/src/index.ts`의 인터페이스가 유일한 진실이다. 새 필드는 여기서 먼저 정의하고 양쪽을 맞춘다.
3. **프론트는 KIS를 모른다.** 프론트가 KIS 자격증명·엔드포인트·필드명을 참조하는 순간 설계 위반이다.
4. **단일 상류 연결, 다중 하류 팬아웃.** KIS 실시간 WS는 서버당 1개만 맺고, 프론트 N명에게 broadcast한다. 프론트가 늘어도 KIS 연결은 1개다.

## 주요 설계 결정과 이유

| 결정 | 이유 |
|------|------|
| `shared`를 빌드 없이 소스(`src/index.ts`) 직접 참조 | 타입 전용 패키지라 컴파일 산출물이 불필요. tsx/vite가 소스를 그대로 소비 |
| `access_token`을 파일 캐시(`.cache/token-{env}-{계좌id}.json`) | KIS 발급 횟수 제한. 24h 유효, 만료 1분 전까지 재사용. 계좌마다 앱키가 달라 **앱키별로** 분리한다 |
| 토큰 발급에 in-flight Promise 공유 | 계좌 API 3개가 동시에 뜨면 같은 앱키로 토큰을 중복 발급한다. 발급 중인 Promise를 재사용해 1회로 묶는다 |
| `approval_key`는 메모리 캐시 (앱키별 Map) | WS 접속용, 프로세스 수명 동안만 유효하면 충분 |
| 앱키/시크릿을 전역 값이 아니라 `KisAccountConfig`로 계좌와 묶음 | KIS는 앱키에 등록된 계좌만 조회를 허용한다(`INVALID_CHECK_ACNO`). 전역 앱키로는 두 번째 계좌를 절대 못 본다 |
| 시세·실시간 WS는 기본 계좌 앱키로 고정 | 시세는 계좌와 무관하다. 계좌를 바꿀 때마다 앱키를 갈아타면 호출 한도가 흩어지고 실시간 WS를 재접속해야 한다 |
| REST 헬퍼 `kisGet(path, trId, params)` 공통화 | 모든 조회가 동일한 인증 헤더 + tr_id 패턴. 중복 제거 |
| `KisRealtime`을 `EventEmitter`로 | 파싱(체결/상태)과 중계(broadcast)를 느슨하게 분리. 서버는 `'trade'`/`'status'`만 구독 |
| 실시간 체결로 "오늘 캔들"을 `update` | H0STCNT0 프레임에 당일 시/고/저/현재가가 모두 담겨 있어 추가 조회 없이 마지막 캔들 갱신 가능 |
| 프론트에서 종목별 **최신 체결만** 유지 (`trades[code]`) | 렌더링에 필요한 건 최신값. 전체 히스토리를 메모리에 쌓지 않는다 |
| 자동 재접속 (백엔드 KIS·프론트 스트림 양쪽) | 3초 후 재연결, 재접속 시 구독 전량 재등록 |
| 매수가능 조회는 시장가에 단가를 넣지 않음 (`ORD_DVSN='01'` + `ORD_UNPR='0'`) | KIS가 주문구분에 따라 계산 근거를 바꾼다. 시장가에 단가를 넣으면 응답이 왜곡되고, 지정가에 단가를 빼면 수량이 0으로 내려온다 |
| 실계좌 매수가능 한도는 paper 주문을 **차단하지 않고 경고만** | paper 계정 주문을 실계좌 잔고로 막으면 시뮬레이션이 성립하지 않는다. 실주문 게이트(4단계)를 위한 사전 신호로만 쓴다 |
| 체결내역에 미체결·취소·거부까지 포함 | 감사 기록이 목적이라 "왜 안 됐는지"가 성공 기록만큼 중요하다 (`blocked` 주문을 남기는 것과 같은 이유) |
| 지수업종을 별도 테이블이 아니라 `instruments` 컬럼으로 | 종목당 대분류 1 + 중분류 1로 끝나는 1:1 속성이라 `asset_type`과 같은 성격이다. 테이블을 나누면 종목 조회 여덟 곳이 전부 조인을 달아야 한다 |
| 업종을 코드와 이름 **둘 다** 저장 | 코드는 시장마다 다른 체계라(제조 = KOSPI `0027` / KOSDAQ `1009`) 시장을 넘어 묶으려면 이름이 있어야 한다. 반대로 업종 지수 시세 조회는 코드를 받는다. 이름만 두면 조회를 못 하고, 코드만 두면 화면에 `0027`이 찍힌다 |
| 업종 이름을 못 찾으면 동기화를 **던져서** 멈춤 | 코드가 표에 없다는 것은 꼬리가 밀렸거나 코드 마스터가 낡았다는 뜻이다. 이름을 비워 담으면 "업종 없는 종목"과 구별되지 않는다 |
| 종목 열 목록·행 변환을 `db/instruments.ts` 하나에서 내보냄 | 같은 `SELECT` 목록이 `instruments.ts` 여덟 곳 + `trading.ts` 여섯 곳에 사본으로 있었다. 열을 하나 더할 때 한 곳을 빠뜨리면 그 경로만 조용히 값이 빈다 |
| 테마는 컬럼이 아니라 **N:M 테이블**(`themes` + `theme_instruments`) | 업종과 달리 종목당 여러 개다 — 삼성전자 16개, 평균 2.37개. 컬럼으로는 담을 수 없다 |
| `theme_instruments`에 `symbol`과 `instrument_id`를 **둘 다** 저장 | 마스터가 9개월 낡아 고유 2,333종목 중 220종목이 지금 종목 마스터에 없다. 매칭된 것만 담으면 "반도체 110종목"이라고 적고 101종목만 보여 주게 된다. 원본 사실(`symbol`)을 남기고 연결(`instrument_id`)만 nullable로 붙인다 |
| 테마 기준일(`source_modified_at`)을 302개 테마 행마다 저장 | 조회 여덟 갈래가 메타 테이블을 조인하지 않아도 "언제 것인지"를 함께 들고 나가게 하려고. 값이 하나뿐이라 중복이지만, 조인 하나를 빠뜨려 기준일 없이 목록만 나가는 쪽이 더 위험하다 |
| 시세 복수 조회를 **호출 수**로 상한 잡음 (`MAX_PRICE_LOOKUP_CALLS` · `MAX_SCREENING_CALLS`) | 예전 상한(24 / 80)은 "종목당 1회"라 종목 수가 곧 호출 수였다. 멀티시세는 30종목이 1회라 종목 수만 적어 두면 몇 회가 나가는지 아무도 모른다 |
| 멀티시세 결과를 `quotes` / `blank` / `failed` 셋으로 나눔 | "그런 종목이 없다"와 "조회가 깨졌다"는 다른 사실이다. 하나로 뭉치면 화면이 실패를 "값 없음"으로 적는다 |
| 멀티시세 응답 자리를 **코드로 검산**하고 어긋나면 던짐 | 한 칸 밀려도 나오는 값이 다른 종목의 그럴듯한 가격이라 형식 검사로는 안 걸린다. 042700이 069500의 가격을 받는 식이다 |
| `Quote.turnover`를 선택 필드로 (없으면 안 담음) | KIS가 `acml_tr_pbmn`으로 실제 누적 거래대금을 준다(단건·멀티 둘 다). 해외·선물·야간 환산가는 안 준다 — 0으로 채우면 "오늘 한 주도 안 거래됐다"가 되고, 어림값을 채우면 어림인지 알 수 없게 된다 |
| 테마 등락률의 대표값은 **중앙값** (평균·거래대금 가중도 함께 담음) | 테마 종목 수가 1~110이라 작은 테마에서는 한 종목의 상한가가 단순평균을 통째로 끌어간다. 거래대금 가중은 대형주 하나로 수렴한다. 셋은 성질이 다르므로 합치지 않고 나란히 둔다 |
| 거래대금 가중은 **거래대금이 온 종목만으로** 계산 (어림하지 않음) | `현재가 × 거래량` 어림은 113종목 실측에서 −6.68% ~ +6.24%로 어긋난다. 가중치가 어림값이면 결과가 어림인지 알 수 없다. 뺀 종목 수(`turnoverCount`)를 함께 준다 |
| 테마 등락률 예산을 넘기면 **테마 단위로 통째로 뺌** (`skipped`) | 110종목 중 30종목만 보고 낸 값을 "반도체 테마 등락률"이라 부를 수 없다. 반쪽으로 재느니 안 잰다 |
| `/api/instruments/quotes` 상한을 종목 수 360 → **조회 10회(=300종목)** 로, 넘치면 400 | 360은 "12회"라는 뜻인데 숫자로는 종목 수뿐이었고, 12회는 재 보지 않은 값이다(실측 최대는 10묶음). 넘친 요청을 잘라 200으로 답하면 멀티시세의 31종목 함정을 우리 API가 한 겹 더 만든다 |
| 묶음 크기(`INSTRUMENT_QUOTE_BATCH`)를 shared에 둠 | 프런트가 8씩 보내던 때 120종목 목록이 15요청 15조회였다. 서버가 30종목마다 1회로 처리하므로 배수로 보내야 이득이 난다. `KRX_SESSION_MINUTES`와 같은 이유로 한곳에 둔다 — 양쪽이 각자 숫자를 들면 한쪽만 고쳤을 때 조용히 갈라진다 |

### 부호(sign) 규약 (KIS 공통)
`1`=상한, `2`=상승, `3`=보합, `4`=하한, `5`=하락. 색상 매핑은 상승계열(1/2) 빨강, 하락계열(4/5) 파랑 — **한국 관례(상승=적색)** 를 따른다.

## 새 기능 추가 시 따라야 할 패턴

### 새 KIS 조회 추가
1. `shared/src/index.ts`에 응답 타입 정의
2. `backend/src/kis/rest.ts`에서 `kisGet()`로 호출 → 원본을 새 타입으로 정규화
3. `server.ts`에 라우트 추가 (로직 X, 위임만)
4. `frontend/src/api.ts`에 fetch 함수 추가

### 새 실시간 TR 구독 추가
1. `shared`에 정규화 타입 + `ServerMessage` 유니언에 variant 추가
2. `realtime.ts`에 TR_ID 상수·구독·프레임 파서 추가 → 새 이벤트 emit
3. `server.ts`에서 이벤트 → broadcast 연결
4. `useStream.ts`에서 새 메시지 타입 소비

> 규칙: 원본 필드는 `kis/`를 넘지 않는다. 유니언 추가 시 프론트의 `switch`도 함께 갱신(exhaustive).

### 공개 마스터 파일 받기

받는 곳은 `https://new.real.download.dws.co.kr/common/master/<이름>.mst.zip`이고
**인증이 필요 없다**(appkey·토큰과 무관하다). 실전/모의 구분이 없으므로 `config.ts`
분기 대상이 아니다. 받는 대상은 국내 5종
(`kospi_code`·`kosdaq_code`·`konex_code`·`idxcode`·`theme_code`)뿐이다 —
해외(`*MST.COD`)·선물(`ffcode.mst`)은 경로와 형식이 달라 아직 손으로 넣는다.

`kis/masterArchive.ts`가 zip을 풀고 `kis/masterDownload.ts`가 받기·검증·갈아끼우기를 한다.
`npm run sync:instruments`가 맨 앞에서 부르고, 따로 돌리려면 `npm run download:masters`다.

#### ★ zip 내부 타임스탬프를 파일 mtime으로 옮긴다

**zip은 매일 재포장되지만 내용은 안 바뀐다.** 2026-07-30 실측:

| 파일 | 응답 `Last-Modified` | zip 내부 타임스탬프 |
|------|------|------|
| `kospi_code.mst` · `kosdaq_code.mst` | 2026-07-30 18:55 KST | 2026-07-30 07:35 |
| `konex_code.mst` | 2026-07-30 18:55 KST | 2026-07-30 05:58 |
| `idxcode.mst` | 2026-07-30 18:55 KST | **2026-05-21 16:16** (70일) |
| `theme_code.mst` | 2026-07-30 18:55 KST | **2025-11-06 05:58** (266일) |

`themes.source_modified_at`이 파일 mtime에서 오고 화면에 `기준일`로 뜬다. 시각을
안 옮기면 9개월 묵은 테마 명단이 "오늘 것"이 된다. 그래서 `utimes`로 얹고 **그 뒤에**
`rename`한다 — 순서를 뒤집으면 잠깐이지만 오늘 날짜의 파일이 노출된다.

시각은 두 군데에 들어 있고 **정밀도가 다르다.** DOS date/time은 로컬 시간 2초 단위,
Info-ZIP `UT` 확장 필드(0x5455)는 UTC epoch 초 단위다. `theme_code`가 각각 05:58:10과
05:58:09이고, 손으로 넣던 시절 파일의 mtime이 **05:58:09**이라 `UT` 쪽과 맞는다
(macOS `unzip`이 그렇게 푼다). 우리도 `UT`를 먼저 보고 없을 때만 DOS로 물러선다.
그래야 이미 받아 둔 파일과 새로 받은 파일의 기준일이 2초씩 어긋나지 않는다.

#### 실패하면 기존 파일을 그대로 둔다

마스터가 통째로 날아가면 앱이 종목을 잃는다. 순서가 **메모리로 받기 → zip 검증
(길이·CRC32) → 실제 파서로 끝까지 읽기 → 임시 파일 + `utimes` → `rename`**이라
어디서 실패해도 기존 파일에 손이 닿지 않는다. 임시 파일은 같은 디렉터리에 둔다 —
파일시스템이 다르면 `rename`이 복사가 되어 원자성이 깨진다.

CRC32는 `zlib.crc32`를 쓰지 않고 표를 직접 만든다. 그 API는 Node 20.15+에만 있고
레포의 `engines`는 `>=20`이다. 실측으로 **압축 데이터 한 바이트를 뒤집으면 inflate도
길이 검사도 통과하고 CRC만 잡아낸다.**

**행 수가 줄어도 막지 않는다.** 상장폐지로 실제로 줄기 때문이다 — 막으면 영영 낡은
파일로 돌게 된다. 대신 이전/이후 행 수를 로그에 나란히 적는다. 하드 차단은 **행이
0개일 때**뿐이다(`assertMasterContent`). 파서들은 행마다 검사하므로 행이 0개면 아무
말 없이 통과한다.

`kis/masterDownload.ts`가 던지는 대신 결과(`status`·`usable`)로 넘기고,
**쓸 파일이 아예 없을 때만** `syncInstruments`가 던진다.

#### 얼마나 자주 받는가 — 12시간

파일은 하루 한 번 만들어진다(내부 타임스탬프 05:58~07:35 KST). **12시간 안에 받은
것은 다시 받지 않는다.** 조건부 GET은 쓸 수 없다 — `Last-Modified`가 매일 오늘이라
304가 돌아오지 않는다.

"언제 받았나"는 파일 mtime으로 알 수 없다. mtime은 일부러 **내용 기준일**로 덮기
때문이다. 그래서 받은 시각은 `backend/.cache/master-download.json`에 따로 적는다
(`themes.source_modified_at`과 `synced_at`을 나눠 둔 것과 같은 이유).
`--force`로 무시하고, `sync:instruments --no-download`로 아예 끈다.

### 종목 마스터(.mst) 필드 추가

레이아웃과 행 파서는 `backend/src/kis/domesticMaster.ts` 하나에 둔다.
`syncInstruments.ts`는 정규화만 하고 자리 계산은 하지 않는다.

국내 마스터는 EUC-KR **고정폭**이다. 앞 61바이트는 세 시장이 같고
(단축코드 9 + 표준코드 12 + 한글종목명 40), 꼬리 길이만 다르다 —
실측(2026-07) KOSPI 227 / KOSDAQ 221 / KONEX 184.

**KIS 공식 파이썬 파서의 상수(`row[0:len(row) - 228]`)를 그대로 옮기지 마라.**
파이썬의 `for row in f`가 주는 row에는 줄 끝 개행 1글자가 들어 있다. 개행을 뗀
문자열에 같은 수를 쓰면 한글종목명 끝 한 글자를 잘라 먹는다. 대부분은 이름 뒤
공백이 잘려 `.trim()`이 삼키므로 드러나지 않고, 이름이 40바이트를 꽉 채운 행만
`…(합성` 처럼 티가 난다. 그 상태로 꼬리 필드(업종 등)를 읽으면 전부 한 칸 밀린다.

**시장마다 다르므로 일괄로 1을 빼지도 마라.** KONEX 184는 원래 맞는 값이었다.
새 시장·새 파일을 붙일 때는 행 바이트 수를 직접 재서 `꼬리 = 행 바이트 − 61`로
구하고, 꼬리 첫 필드인 증권그룹구분코드(대문자 2글자)로 정렬을 확인한다 —
`parseDomesticMasterRow`가 매 행 검사하고 어긋나면 던진다. 조용히 건너뛰지 않는다.

#### 지수업종 (꼬리 [3,7)·[7,11))

꼬리 앞쪽은 `증권그룹구분코드 2 · 시가총액규모 1 · 지수업종 대분류 4 · 중분류 4 · 소분류 4`다.
값이 없으면 `0000`으로 채워 오므로 **`0000`은 NULL로 바꾼다** — 없는 것과 0은 다르다.

**꼬리 레이아웃은 시장마다 다르다. KOSPI/KOSDAQ의 자리를 KONEX에 그대로 쓰면 안 된다.**
KONEX 꼬리의 같은 자리에도 숫자가 들어 있어 형식 검사로는 걸러지지 않는다(실측
2026-07-31: 중분류 자리 값 107개가 전부 `idxcode.mst`에 없는 값). `DomesticMasterSpec.
hasIndexSectorFields`로 시장별로 켠다.

**한 칸 밀려도 숫자 4자리가 나온다는 것이 이 필드의 함정이다.** 왼쪽으로 한 칸 밀면
시가총액규모를 끌어와 삼성전자가 `1002`(코스닥 대형주)로 읽힌다 — 실재하는 코드다.
그래서 형식이 아니라 **값으로** 확인한다. 자리가 맞으면 KOSPI·KOSDAQ의 업종 코드가
**하나도 빠짐없이** `idxcode.mst`에 있다(실측 4,207개 전부). 하나라도 없으면 던진다.

소분류(`[11,15)`)는 읽지 않는다. 필드는 3단인데 데이터는 2단이다 — 실측에서 국내
4,502행이 **전부** `0000`이었다(2026-07-30자 마스터). "3단 분류가 있다"고 적지 마라.

코드→이름은 `idxcode.mst`(인증 불필요, 491행)에 있고 `indexSectorMaster.ts`가 읽는다.
KIS 공식 파서(`sector_code.py`)의 이름 자리(`row[3:43]`)는 **틀렸다** — 이름 앞에 코드 뒤
2자리가 붙어 `0001`이 `'01종합'`이 된다. 실제 이름은 `row[5:]`부터다.

## 멀티시세 — 한 번에 30종목 (`FHKST11300006`)

`/uapi/domestic-stock/v1/quotations/intstock-multprice`. 파라미터는
`FID_COND_MRKT_DIV_CODE_1..30` + `FID_INPUT_ISCD_1..30`이고 번호는 **1부터**다.
시장 구분은 주식·ETF 모두 `J`(KRX)다.

2026-07-31 실계좌(prod, 장 마감 후)로 재서 확인한 것:

| 물음 | 실측 |
|------|------|
| 응답 형식 | 최상위 `output` **배열** 하나. `output1`/`output2`로 나뉘지 않는다 |
| 행당 필드 | 29개. 값은 `inter2_` 접두사, 코드·이름만 `inter_` 접두사 |
| 30종목 | 30행. **요청 순서 그대로** |
| **31종목** | **`rt_cd=0`으로 정상 응답하면서 30행만 온다.** 31번째는 조용히 사라진다 |
| 20종목 | 20행. 파라미터를 덜 채워도 된다 |
| 없는 코드(`999999`) | **그 자리만 전 필드가 빈 문자열인 행**으로 온다. 통째로 실패하지 않는다 |
| ETF | 된다 (`069500`·`122630` 확인) |
| 단건(`FHKST01010100`)과 값 | 현재가·전일대비·등락률·부호·시가·고가·저가·거래량·**거래대금**이 전부 일치 |
| 연속 호출 | 10묶음 300종목을 1.08초에 받음. `EGW00201` 0건 |

**31종목이 오류가 아니라는 것이 이 API의 함정이다.** `rt_cd=0`을 받고도 종목이
빠진 채로 "이 테마는 이게 전부"라고 적게 된다. 그래서 30을 넘겨 부르지 않고
(`multiQuoteParams`가 던진다), 응답 자리를 **코드로 검산**한다.

### 값이 없을 때 단건과 다르게 말한다

상장 직후라 시세가 없는 ETF(`0021C0` ACE TDF장기자산배분액티브 등 3종목)를
물으면 **단건은 `stck_prpr = 0`을 주고 멀티는 빈 문자열을 준다.** 멀티 쪽은
`blank`로 갈라낼 수 있고, 단건 쪽은 `현재가 0원`이라는 없는 사실을 만든다.
부르는 쪽이 `price <= 0`을 따로 거르는 이유가 여기 있다.

### 빈 문자열은 0이 아니다

`Number('')`은 **0**이다. KIS는 값이 없는 자리에 빈 문자열을 주므로 그냥 읽으면
"값 없음"이 "0"이 된다. 없는 종목코드가 **전 필드 빈 문자열 행**으로 오는 이 API에서
특히 드러난다 — 거래대금이 0으로 잡히면 "오늘 한 주도 안 거래됐다"는 사실이 된다.
`normalize.ts`의 `toNumberOrNaN`이 이것만 담당한다.

### 누적 거래대금 — 어림을 걷어냈다

`acml_tr_pbmn`이 단건·멀티 둘 다에 있다. 예전에는 유동성 판정이
`현재가 × 누적거래량`으로 어림했다. `Quote.turnover`로 실제 값을 담고,
이 값을 안 주는 경로(해외·선물·야간 환산가)만 어림값으로 물러선다.

**어림의 오차를 한 종목으로 재지 마라.** 어림은 `종가 × 거래량`이고 실제는
`VWAP × 거래량`이라, 오차 = `(VWAP − 종가) / 종가`다. 2026-07-30 스크리닝 풀
113종목 실측에서 **중앙값 +0.28% · 범위 −6.68% ~ +6.24%**로 부호가 양쪽이었다.
005930 하나만 보면 +2.59%인데, 그 값을 일반화해 문서 세 곳에 "2.5%"라고
적었다가 검증에서 걸렸다. 등락률과의 상관이 r = −0.768이라 **하락일에는 작게,
상승일에는 크게** 나온다.

같은 실측에서 유동성 판정이 뒤집힌 종목은 0/113이었지만 안전하다는 뜻은 아니다 —
`000105 유한양행우`가 문턱 대비 −1.9%로 아슬아슬했고, 반도체 표본에서는 +4.78%가
실제로 나왔다. 다른 날·다른 풀에서는 뒤집힌다고 봐야 한다.

## 테마 분류

### 왜 업종으로 안 되는가

업종에는 `반도체`라는 칸이 **없다.**

| 종목 | 지수업종 | 테마 |
|------|------|------|
| 005930 삼성전자 | 제조 / 전기·전자 | HBM, CXL, 온디바이스AI, 3D낸드, 폴더블폰 … 16개 |
| 247540 에코프로비엠 | 제조 / 전기·전자 | 2차전지(소재,부품,장비), 전기차, 2019 신규 상장주 |
| 012450 한화에어로스페이스 | 제조 / 운송장비·부품 | 방위산업, 우주(위성,발사체), UAM, 로봇 … 7개 |
| 042660 한화오션 | 제조 / 운송장비·부품 | 조선, LNG, 셰일가스 |

`theme_code.mst`(인증 불필요, 5,528행)에 302개 테마가 있고 `themeMaster.ts`가 읽는다.
레이아웃은 `[0,3) 테마코드 · [3,43) 테마명(40바이트) · [43,52) 단축코드(9바이트)`다.

**고정폭인데 글자로 잘라도 되는 이유를 코드 주석에 남겼다.** 자르는 자리가 둘 다
ASCII 구간이고 그 구간의 **바깥쪽 끝에서** 재기 때문이다(앞에서 3, 뒤에서 9). 한글은
가운데에만 있다. **앞에서 43글자를 세면 안 된다** — 거기는 한글을 지나가는 자리다.

⚠ **KIS 공식 파서(`theme_code.py`)의 `row[-10:]`을 그대로 옮기면 안 된다.** 그 `10`은
`9 + 개행 1`이다 — 파이썬의 `for row in f`가 주는 row에 줄 끝 개행이 들어 있어서,
**공식 파서도 실제로는 `[0,3) / [3,43) / [43,52)`로 자른다. 상수 자체는 우리와 같다.**
`domesticMaster.ts`의 꼬리(228 = 227 + 개행)와 정확히 같은 −1이고, 두 곳이 같은 이유로
1씩 다르다.

개행을 뗀 뒤 10을 세면 테마명 필드의 마지막 바이트를 끌어온다. 지금은 테마명이 최대
24바이트뿐이라 그 자리가 늘 공백이고 trim이 삼켜 **결과가 똑같이 나온다.**
그래서 값만 보는 검사로는 절대 안 걸린다 — 자른 **원본** 모양(앞 글자가 공백인가)까지
봐야 한다. 실제로 `row[-10:]` + trim 검사로 구현하면 시험 16개 중 14개가 통과하고,
실측 파일로 재는 시험 넷도 전부 통과한다.

### 이 마스터는 낡는다 — 그 사실을 데이터에 남긴다

zip은 매일 재포장되지만 내용은 갱신되지 않는다. 2026-07-31에 받은 파일이 2025-11-06자였다
(`2018 신규 상장주`~`2024 신규 상장주`는 있어도 2025·2026은 없다). 그래서 목록만 넘기면
화면이 "지금 반도체 테마"라고 말하면서 9개월 전 명단을 보여 주게 된다.

낡음을 두 값으로 남긴다.

1. `themes.source_modified_at` — 마스터 파일의 수정 시각(zip 내부 타임스탬프). **우리가
   받아온 시각이 아니다.** `synced_at`을 따로 두어 둘을 섞지 않는다. 받아 오는 쪽이
   `utimes`로 이 시각을 파일에 얹으므로(「공개 마스터 파일 받기」 절) 매일 받아도
   기준일은 2025-11-06 그대로다. 다만 파일을 `cp`로 옮기면 시각이 오늘로 바뀐다.
2. `Theme.symbolCount` vs `Theme.instrumentCount` — 마스터가 넣어 둔 수와 지금 찾은 수.
   **합치지 않는다.** 2026-07-31 실측(종목 마스터 2026-07-30자)으로 고유 2,333종목 중
   220종목이 지금 종목 마스터에 없고(쌍으로는 432/5,528),
   **302개 테마 중 197개에 구멍이 나 있다.**

**2번은 종목 마스터를 새로 받을수록 커진다.** 테마 명단은 멈춰 있는데 종목 쪽만
새것이 되기 때문이다 — 2026-07-10~11자 종목 마스터로는 218종목·425쌍·192테마였고,
20일 새 2026-07-30자로 바꾸자 220종목·432쌍·197테마가 됐다. 더존비즈온(012510)·
현대홈쇼핑(057050)이 그 20일 사이 종목 마스터에서 빠진 예다.

못 찾은 종목코드는 `ThemeMembers.missingSymbols`로 그대로 넘긴다. 빈 값으로 지우면
`110종목 중 101종목`이라고 적을 수 없다.

ETF에는 테마가 붙지 않는다 (실측: 오늘자 마스터 ETF 1,153종목 중 0건). 테마 화면에
ETF가 안 보이는 것은 결함이 아니다.

### 스키마

```sql
themes             (code PK, name, source_modified_at, synced_at)
theme_instruments  (theme_code FK→themes CASCADE, symbol, instrument_id FK→instruments SET NULL,
                    PRIMARY KEY (theme_code, symbol))
```

- **PK 앞자리가 `theme_code`**라 "테마 하나의 종목 목록"이 인덱스 앞부분 스캔으로 끝난다.
  다음 단계인 멀티시세(`FHKST11300006`, 한 번에 30종목)가 테마마다 이 질의를 때린다 —
  실측 `방위산업 26종목 = 0.2ms`.
- `instrument_id`는 **`ON DELETE SET NULL`**(`trading_broker_orders`와 같은 방식).
  RESTRICT면 9개월 묵은 테마 데이터가 종목 삭제를 막고, CASCADE면 "이 테마에 이런 종목이
  있었다"는 사실 자체가 사라진다. 연결만 끊고 사실은 남긴다.
- 동기화는 지웠다 넣는다(`instruments`의 `is_active` 방식과 다르다). 테마를 참조하는
  다른 테이블이 없고, 마스터에서 빠진 테마를 남겨 두면 "지금 있는 테마"와 구별되지 않는다.

### 테마 등락률 — 무엇을 대표값으로 둘 것인가

`backend/src/themes/pulse.ts`. 집계는 순수 함수(`aggregateThemePulse`)로 떼어 DB·네트워크
없이 시험한다. 세 값을 **다 담고** 대표는 **중앙값**이다.

| 값 | 무엇을 말하는가 | 왜 대표가 아닌가 |
|------|------|------|
| **중앙값** | 이 테마 종목의 절반이 이보다 위 | — (대표) |
| 단순평균 | 종목을 똑같이 세었을 때의 평균 | 종목 수가 1~110이라 작은 테마에서 한 종목의 상한가(+30%)가 통째로 끈다 |

### 아직 안 고친 것 — 거래가 없는 종목의 `0%`

**거래대금이 0원인 종목의 등락률 0%가 중앙값·단순평균·보합 수에 그대로 들어간다.**
가중평균에서는 `turnover > 0`으로 정확히 뺐는데 나머지 셋에는 남아 있다.

2026-07-31 실측: 반도체 3종목 · 2차전지 4종목 · 방위산업 1종목이 거래대금 0원이고
**등락률이 전부 0%**다. 특히 2차전지는 **보합 4종목이 전부 거래 0원**이라 진짜 보합은
0종목이다. 중앙값에 미치는 크기:

| 테마 | 지금 | 거래 0원 제외 | 차이 |
|------|------|------|------|
| 2차전지(소재,부품,장비) | +0.810 | +1.090 | **+0.280%p** |
| 반도체/반도체장비 | −2.580 | −2.815 | −0.235%p |
| 방위산업 | +0.445 | +0.560 | +0.115%p |

거래가 한 건도 없는 종목의 `0%`는 "안 움직였다"가 아니라 **"오늘 값이 없다"**에 가깝다.
`docs/CODE_STYLE.md`의 「값이 없는 것과 0인 것은 다르다」와 부딪히지만, 어느 쪽으로 셀지는
측정이 아니라 **판단**이라 고치지 않고 남긴다. 함께 알아 둘 것: `turnoverCount`는 지금
「거래대금 필드가 안 온 종목」과 「0원인 종목」을 한 칸에 합쳐 뺀다(실측 3테마에서는
전부 후자였다).

**표본은 네 번 줄어든다.** 마스터 110 → 지금 찾은 101 → 시세 온 101 → 거래대금까지 온 98.
넷을 하나로 합치면 화면이 `반도체 110종목`이라 적고 98개로 낸 값을 보여준다. 줄어든
자리마다 이유가 다르므로(`missingSymbols` · `blankSymbols` · `failedSymbols`) 따로 담는다.

**예산은 호출 수로 잡는다** (`THEME_PULSE_MAX_CALLS = 8`, 240종목). 종목 수로 잡으면 몇
회가 나가는지 알 수 없다. 여러 테마를 한 번에 받는 이유는 겹침이다 — 종목당 평균 2.37개
테마라 따로 부르면 삼성전자를 16번 묻는다.

실측: 반도체 101 + 2차전지 87을 함께 물으면 **합집합 187종목**(겹침 1)이 **7회 0.7초**다.
다만 **이 조합은 합집합의 이득을 보여 주지 못한다** — 따로 불러도 `4 + 3 = 7`회라 같다.
이득이 실제로 드러난 것은 `099 + 306`이다: 자리 수 28 · 고유 22라 **2회가 1회**가 됐다.
예산을 넘기는 테마는 통째로 빼고 사유를 `skipped`에 담는다.
