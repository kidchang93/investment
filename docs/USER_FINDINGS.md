# USER_FINDINGS

> 실제 주문자(개인 투자자) 관점으로 앱을 처음부터 끝까지 써보며 발견한 것을 날짜별로 남긴다.
> 코드 리뷰가 아니라 사용 관점 기록이므로, `docs/ARCHITECTURE.md`·`docs/DESIGN.md`·`docs/CODE_STYLE.md`의
> 기준과 충돌하는 부분은 이 문서가 지적하는 쪽이고 저 문서들이 규범이다.

## 2026-07-27 장중 사용자 관점 점검

### 요약

- **가장 큰 오해를 바로잡음**: 사전 브리핑에는 "지금 앱에 호가창이 없다"고 되어 있었지만, 실제로는 `GET /api/instruments/:id/order-book`가 살아 있고 프런트 `OrderBookPanel`(주문 티켓 맨 위)이 10단계 매도/매수 호가·잔량·동시호가 예상체결·VI(변동성완화장치) 알림까지 렌더링한다. 호가 행을 누르면 지정가 칸에 그 가격이 그대로 들어간다. 이건 고칠 필요 없는 기능이니 다음 점검자는 "호가창이 없다"는 전제로 재조사하지 않아도 된다.
- 실제로 걸린 가장 위험한 지점은 **수동 실계좌 주문 티켓이 자동매매 패널과 달리 `시장가 허용`·`허용/차단 종목` 리스크 룰을 주문 확인 화면 이전에 검사하지 않는 것**이다. 주문 티켓을 열면 기본값이 이미 리스크 룰로 막혀 있는 `시장가`인데도, 확인 단계는 "실계좌 주문입니다. 확인하면 그대로 접수됩니다"라고 말한다(실제로는 서버가 막는다).
- 종목 화면에 처음 들어가면 선택 종목이 진짜 삼성전자가 아니라 주문이 안 되는 "삼성전자 야간 환산가"(NIGHT_PROXY)로 잡혀 있어, 초심자는 이 가격이 지금 살 수 있는 가격인 줄 착각할 수 있다.
- 주문 전 화면 어디에도 수수료·세금 예상액이 없다. `발견 > 도구 > 수수료` 계산기는 있지만 주문 금액과 연결되어 있지 않다.
- 실계좌 예수금이 50,000원뿐이라 삼성전자는 1주도 살 수 없는 상태였다(`실계좌 매수가능 49,751원, 최대 0주` — 실제 API·화면에서 확인). 그래서 "10주 매수 → 체결 확인 → 취소" 흐름은 자금 부족으로 끝까지 실습하지 못했다(아래 "확인하지 못한 것" 참고).

### 확인했지만 멀쩡했던 것

- **호가창은 이미 있고 잘 동작한다.** `종목 > 주문` 탭에서 국내 주식(예: 005930)을 고르면 주문 티켓 맨 위에 10단계 매도/매수 호가·잔량 막대·"09:06:58 기준 · 2초 전" 신선도 표시가 뜨고, 각 호가 행을 누르면 지정가 칸에 그 가격이 채워진다(`OrderBookPanel`, frontend/src/App.tsx:792-889). 동시호가 구간이면 예상 체결가, VI 발동 중이면 경고 문구도 따로 뜬다. 사전 브리핑의 "호가창이 없다"는 전제와 달리 실제로는 구현돼 있었다.
- 실계좌 매수가능 금액이 0원대로 부족할 때 `최대` 버튼은 `disabled={maxOrderQuantity === undefined || maxOrderQuantity <= 0}`로 정확히 잠기고(frontend/src/App.tsx:6489), 안내 문구도 "실계좌 예수금으로는 1주도 살 수 없습니다"처럼 0인 상황을 "최대 0주까지 살 수 있습니다"(살 수 있다는 말처럼 읽히는 문구)로 잘못 말하지 않는다. `CODE_STYLE.md`가 지적한 "0이나 빈 값일 때 문장이 뒤집히지 않는지" 기준을 실제로 지키고 있었다.
- 주문 확인 단계 이전에 실수로 `매수 주문하기`를 눌러도 `취소` 버튼으로 되돌릴 수 있고(frontend/src/App.tsx:6598-6606), `KIS_LIVE_ORDER_ENABLED`가 꺼진 지금은 최종 전송 버튼 자체가 잠겨 있어 실수로 실주문이 나갈 여지가 없었다(실측: `매수 주문하기` 버튼이 disabled 상태, 아래에 "실주문이 꺼져 있습니다…" 안내).
- KIS 계좌 조회가 도중에 502로 실패하는 것을 실측으로 봤는데(상단에 `KIS 계좌 조회 실패: 502` 배너), 그 아래 카드의 예수금·평가금액 숫자는 `-`나 0으로 지워지지 않고 마지막으로 받은 값(50,000원)을 그대로 유지했다. `CODE_STYLE.md`의 "받아 둔 값은 그대로 두고 오류만 올린다" 원칙이 실제로 지켜지고 있었다(다만 이 502가 이 점검 중 백엔드에 동시에 여러 API를 두드린 내 테스트 때문에 유발됐을 가능성이 있어, 자연 발생 빈도는 확인 못함 — `docs/TRADING_API.md`의 초당 호출 한도(EGW00201) 항목과 관련).
- 리스크 룰 카드의 `허용 종목` 칸에는 실제 값 "005930"이 굵은 흰 글씨로, `차단 종목` 칸에는 입력 예시가 옅은 회색 placeholder로 "005930"이 떠 있어 얼핏 같은 종목이 허용이면서 차단인 것처럼 보이지만, 실제로는 진하기 차이로 구분돼 있고 `GET /api/broker/kis/risk-rules`도 `symbolBlocklist: []`(빈 배열)를 반환한다 — 헷갈릴 뻔했지만 실제 버그는 아니었다.
- 예수금 50,000원, 삼성전자 현재가 25만원대에서 `실계좌 매수가능` 계산(`GET /api/broker/kis/orderability`)이 `cashBuyQuantity: 0`으로 정확히 나왔고, 주문 티켓의 경고 문구·`최대` 버튼 잠김과 API 응답이 서로 일치했다.

### 확인하지 못한 것

- **실제 주문 접수 → 체결/미체결 확인 → 정정·취소** 전체 흐름을 끝까지 밟지 못했다. 계좌(21) 실제 예수금이 50,000원뿐이라 삼성전자(허용 종목이 이것 하나뿐) 1주도 살 수 없어서(`실계좌 매수가능 49,751원, 최대 0주`), `KIS_LIVE_ORDER_ENABLED=true`로 게이트를 열어도 처음부터 리스크 룰/잔고에 막혀 실제 주문을 넣어볼 수 없었다. 이 작업 지침상 실주문 버튼도 누르면 안 됐으므로 어차피 시도하지 않았다.
- 미체결 주문의 `정정`(단가 입력) UI를 실제로 조작해보지 못했다 — 지금 계좌에 미체결 주문이 0건이라 정정 버튼 자체가 화면에 뜨지 않았다.
- 예약주문을 지금(정규장 중, 09:00~15:30) 등록 시도하면 어떤 메시지가 뜨는지 확인하지 못했다. `docs/TRADING_API.md`는 예약주문이 시간대·개장일 리스크 룰 검사를 건너뛴다고 적어뒀는데, 프런트의 `reservedOrderBlockers`(frontend/src/App.tsx:3550-3562)도 시간 검사를 하지 않아 지금 눌러도 버튼이 막히지 않을 것으로 보이지만, 실제로 KIS가 정규장 중 접수를 어떻게 처리하는지는 실주문이라 시도하지 않았다.
- 장 마감(15:30) 이후 화면이 실제로 어떻게 바뀌는지는 이번 점검 시간(장 시작 직후) 안에 관찰하지 못했다. 코드상 `장외 · 마감 후` 라벨 분기(frontend/src/App.tsx:1401-1412)는 확인했지만 실측은 못 했다.
- "선택 종목이 야간 환산가로 초기화되는" 현상(요구사항 5번)의 정확한 재현 조건 — 한 번 목격했지만 이후 여러 시도에서 재현되지 않았다.
- 계좌 21 외에 `KIS 23` 계좌는 전혀 들여다보지 않았다(잔고·리스크 룰 등 모두 계좌 21 기준).
