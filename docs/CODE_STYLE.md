# CODE_STYLE

기존 코드에서 반복되는 실제 컨벤션이다. 새 코드는 주변 코드와 구분되지 않도록 맞춘다.

## 언어·모듈

- **TypeScript strict + ESM.** 모든 워크스페이스 `"type": "module"`.
- **backend 상대 임포트는 `.js` 확장자 필수.** ESM + tsx 규칙. 예: `import { config } from './config.js';`, `from './kis/rest.js'`.
- **frontend 상대 임포트는 확장자 없음** (Vite 번들러 해석). 예: `from './config'`.
- 공유 타입은 항상 `@invest/shared`에서 임포트. 상대경로로 shared를 파고들지 않는다.
- **타입 임포트는 `import type`** 으로 분리. 예: `import type { Trade, ConnectionStatus } from '@invest/shared';`

## 네이밍

| 대상 | 규칙 | 예시 |
|------|------|------|
| 파일 (backend/로직) | camelCase | `watchlist.ts`, `realtime.ts` |
| 파일 (React 컴포넌트) | PascalCase | `App.tsx`, `Chart.tsx` |
| 훅 | `use` 접두사 | `useStream.ts` |
| 함수/변수 | camelCase | `getDailyCandles`, `approvalKey` |
| 타입/인터페이스/클래스 | PascalCase | `WatchItem`, `KisRealtime` |
| 상수 (모듈 레벨 불변) | UPPER_SNAKE | `TR_TRADE`, `FIELDS_PER_RECORD`, `RECONNECT_MS`, `WATCHLIST` |
| KIS 원본 필드 | KIS 스펙 그대로 (약어) — **단, `kis/` 내부에서만** | `stck_prpr`, `hts_kor_isnm` |

시각 필드 이름은 **무엇의 시각인지**로 고른다. 값 하나를 받아 온 시각은 `fetchedAt`
(`Quote`·`OrderBook`·`ExchangeRate`·`MarketMoversSnapshot`), 한 **회차**를 돌린 시각은
그 회차가 한 동작으로 부른다 — 후보를 거른 회차는 `scannedAt`, 테마 등락률을 잰
회차는 `measuredAt`. 셋이 갈라져 있는 것은 실수가 아니라 대상이 다른 것이다.
새 타입에 시각을 넣을 때 이 셋 중 어디인지 먼저 정한다.

## 주석

- **한국어 주석.** 파일 상단에 그 모듈의 역할·주의점을 블록 주석으로 요약한다 (기존 모든 파일이 이 패턴).
- "왜"를 적는다. KIS 스펙의 함정(필드명 차이, 프레임 포맷, 발급 제한 등)은 반드시 주석으로 남긴다.
- 섹션 구분에 `// ── 제목 ────` 스타일 구분선 사용 (server.ts 참고).

## 함수/타입 스타일

- **명시적 반환 타입.** 공개 함수는 반환 타입을 적는다. 예: `export async function getQuote(code: string): Promise<Quote>`, `function signColor(sign: string): string`.
- 순수 헬퍼는 파일 하단 또는 사용처 근처에 작은 함수로 분리 (`yyyymmdd`, `toCandlestickData`, `formatPrice`).
- 외부 JSON은 `as Record<string, unknown>` / `as Record<string, string>`로 받은 뒤 `Number(...)`로 좁혀 정규화한다. `any` 금지.
- **빈 문자열을 `Number()`에 그냥 넣지 않는다.** `Number('')`은 `NaN`이 아니라 **0**이다.
  KIS는 값이 없는 자리에 빈 문자열을 주므로 그대로 읽으면 "값 없음"이 "0"이 된다 —
  멀티시세는 없는 종목코드를 **전 필드 빈 문자열 행**으로 돌려주고, 거래대금이 0으로
  잡히면 "오늘 한 주도 안 거래됐다"는 사실이 지어진다. `kis/normalize.ts`의
  `toNumberOrNaN`을 쓴다.
- `??`(nullish)와 옵셔널 체이닝 적극 사용. 기본값은 정규화 지점에서 부여.

## React 컨벤션

- 함수형 컴포넌트 + 훅. `export function App(): JSX.Element`.
- `useEffect` 의존성 배열 정확히. cleanup에서 소켓/타이머/차트 정리 (`useStream`, `Chart` 참고).
- WebSocket·차트 인스턴스 등 렌더 사이 유지 대상은 `useRef`. 렌더에 반영할 값만 `useState`.
- 상태 갱신은 불변 업데이트: `setState((s) => ({ ...s, trades: { ...s.trades, [code]: t } }))`.
- 스타일은 `styles.css` 클래스 기반 (BEM 유사: `watch-row__price`). 인라인 스타일은 동적 색상 등 최소한만.
- 누르는 것은 `<button>`으로 만든다. `<span role="button" tabIndex={0}>`은
  `onKeyDown`을 직접 달지 않는 한 Enter·Space로 눌리지 않는다 — 관심종목 +/−
  토글이 그랬고, 마우스로만 됐다. 한 줄에 동작이 둘이면 버튼을 겹치지 말고
  나란히 둔다. 행 전체가 버튼이고 그 안에 토글이 들어 있으면 버튼 속 버튼이라
  HTML로 성립하지 않는다. 바깥을 `<div>`로 바꾸고 안에 진짜 버튼 둘을 둔다.
  `cursor`·`text-align` 같은 버튼 속성도 실제로 눌리는 쪽으로 옮긴다.
- 이름이 기호뿐인 버튼(`+`, `−`, `×`)에는 `aria-label`로 무엇에 대한 동작인지
  적는다. 낭독기에는 `더하기 버튼`으로만 들린다. `title`은 마우스에만 보인다.
- **같은 글씨의 버튼이 한 화면에 여럿이면 `aria-label`로 대상을 밝힌다.**
  `내 계좌`에 `새로고침`이 다섯 개(시세·잔고·체결 내역·주문 기록·예약주문)
  있었다. 눈으로는 어느 카드 안인지로 구별되지만 버튼만 훑으면 구별되지 않는다.
  보이는 글자는 그대로 두고 이름만 늘린다 — `잔고 새로고침`.
  브라우저에서 이렇게 훑는다:

      [...document.querySelectorAll('button')]
        .filter((b) => b.offsetParent)
        .map((b) => b.getAttribute('aria-label') || b.textContent.trim())
        // 같은 이름이 둘 이상인 것을 센다
- 아직 연결되지 않은 컨트롤은 눌리는 것처럼 두지 않는다. 뉴스룸의 `알림 대기`
  ·`음성 읽기`·`공유 링크`가 `onClick` 없이 동작하는 버튼과 똑같이 생긴 채로
  있었다. `disabled`를 걸고 **왜 막혔는지 화면에 적는다** — 흐려진 버튼만으로는
  고장인지 준비 중인지 구별되지 않는다. 채팅 입력칸(`disabled` + placeholder에
  사유)이 같은 방식이다. `:hover`는 `:not(:disabled)`로 좁힌다.
- 필터가 두 갈래 이상이면 갈래마다 이름을 붙이고 `role="tablist"`도 따로 둔다.
  캘린더의 지역·중요도가 한 `tablist`에 섞여 있어 `전체` 버튼 두 개가 나란히
  눌린 채 떠 있었다. 화면에는 어느 쪽이 무엇을 거르는지 적혀 있지 않았고,
  낭독기에는 선택이 둘인 `tablist`로 들렸다. 이름은 `<span id>` +
  `aria-labelledby`로 붙여 `tablist` 자식은 탭만 남긴다.

## 금지 패턴

- ❌ `kis/` 밖에서 KIS 원본 필드명 사용
- ❌ 프론트에서 KIS 자격증명/도메인 직접 참조
- ❌ `any` (외부 JSON은 `unknown` 경유 후 좁히기)
- ❌ backend 상대 임포트에서 `.js` 누락
- ❌ vts/prod 도메인·포트 하드코딩 (`config.ts` 경유)
- ❌ 매 요청마다 토큰 재발급 (캐시 우회)
- ❌ `console.log` 디버그 잔여물 (백엔드는 Fastify `app.log`/`req.log` 사용)

## 포맷

- 들여쓰기 2칸, 세미콜론 O, 문자열 작은따옴표, trailing comma O.
- `tsconfig`: `strict`, `noUnusedLocals`, `noUnusedParameters` (frontend). 미사용 변수/파라미터는 빌드 실패로 이어지므로 남기지 않는다.

## 화면 용어

같은 것을 한 가지 말로만 부른다. 예전에는 연습용 계좌 하나를 화면에서
`Paper KRW` · `PAPER` · `paper` · `모의` · `시뮬` · `테스트매매` · `가상`
일곱 가지로 불러, 처음 보는 사람은 이것들이 같은 계좌인지 알 수 없었다.

| 개념 | 쓰는 말 | 쓰지 않는 말 |
|------|------|------|
| 실제 돈이 오가는 계좌 | `실계좌` | 실전, LIVE, 라이브 |
| 연습용 계좌 | `모의계좌` | Paper, PAPER, paper, 시뮬, 테스트매매, 가상 |
| 연습용 계좌로 하는 매매 | `모의투자`, `모의 주문`, `모의 매수/매도` | 시뮬레이션, 가상 매수/매도, 테스트매매 |
| 데이터를 다시 받는 동작 | `새로고침` | 갱신(동작), 리프레시 |
| 마지막으로 받은 시각 | `갱신 10:52:57`, `갱신 3초 전` | 조회 3초 전, 마지막 조회 |
| 아직 시세가 안 온 항목 | `시세 대기` | 조회 대기 |
| 계좌·체결 데이터를 아직 안 받음 | `조회 대기` | — |
| 실주문 게이트 상태 | `주문 가능` / `주문 잠김` / `확인 중` | 조회 전용, 조회 전용 세션, 전송 잠김, 전송 가능, 실주문 세션, 게이트 확인 중 |
| KIS 서버 환경 | `실전 서버` / `모의 서버` | prod, vts |

`모의계좌`(우리 연습 계좌)와 `모의 서버`(KIS의 모의투자 서버)는 다른 것이다.
KIS 환경을 가리킬 때는 반드시 `서버`를 붙인다.

코드 내부 식별자(`mode: 'paper'`, `TradingMode`)는 그대로 둔다. 화면에 나가는
문자열만 위 표를 따른다.

한 상태를 여러 화면에서 보여줄 때 각 화면이 제 나름의 말을 붙이지 않는다.
`liveOrderGate.enabled` 하나가 헤더에서는 `조회 전용`, 하단 도크에서는
`조회 전용 세션`, 주문 패널에서는 `전송 잠김`이라 불려 한 화면에 세 이름이
동시에 떠 있었다. 같은 값에서 나오면 같은 말을 쓴다.

`조회`는 계좌·체결 데이터를 불러오는 동작에만 쓴다. 한때 읽기 전용 모드
(`조회 전용`), 시세 수신 시각(`조회 3초 전`), 값 없는 칸(`조회 대기`)까지
같은 말을 써서 세 가지 뜻이 겹쳤다.

화면 글에 영어를 남기지 않는다 — `뉴스 ticker`, `검색 기반 fallback`이 그랬다.
`.env`나 환경변수 이름처럼 운영자가 그대로 입력해야 하는 것은 예외다.

내부 식별자를 화면에 찍지 않는다. `Instrument.id`(`KR:KOSPI:005930`,
`KR:NIGHT_PROXY:005930`)는 우리 형식이라 사용자가 읽을 수 없다. 주문 기록의
종목 열이 `005930` · `KR:KOSPI:005930` · `LSE:BC94` 세 형태로 섞여 있었다 —
같은 종목인데 다른 종목처럼 보인다. 표시는 종목코드 하나로 맞추고, 원본
식별자가 필요하면 `title`에 둔다.

`Instrument.market`도 마찬가지다. `KOSPI`·`KOSDAQ`·`NAS`는 실제 시장 이름이라
그대로 두지만, 우리가 만든 구성은 `MARKET_LABELS`에서 한국어로 바꾼다 —
목록에 `005930-NIGHT · NIGHT_PROXY · KRW`처럼 떴었다. 새 market 값을 만들면
이 표에도 넣는다.

| 내부 코드 | 화면 표기 |
|------|------|
| `NIGHT_PROXY` | 야간 환산가 |
| `KRX_NIGHT` | KRX 야간선물 |
| `TV_COMMODITY` | 원자재 |
| `OV_FUT` | 해외선물 |

값이 비면 왜 비었는지 함께 적는다. `-`만 두면 받아오는 중인지 장이 닫힌
것인지 알 수 없다. 종목이 있는 자리면 `pendingQuoteLabel(instrument)`을 쓰고,
사유 글씨는 값보다 한 단계 죽여(`--faint`) 값으로 오해되지 않게 한다.

한 화면 안에서 어투를 섞지 않는다. 카드 부제가 대부분 `-습니다`인데
`차단된 시도도 남는다` 하나만 평서형이었다.

차단 사유는 고쳐서 될 것과 아닌 것을 구분해 배치한다. 게이트가 꺼졌거나
수량이 0인 것은 이 화면에서 고칠 수 있으니 버튼 옆 목록으로 충분하다. 하지만
"이 종목으로는 주문이 안 된다"는 종목을 바꾸는 수밖에 없으므로, 폼을 채우기
전에 위쪽에서 알리고 무엇을 해야 하는지까지 적는다. 예전에는 이 사실이 10px
잔글씨로 버튼 74px 아래에 있어, 수량을 넣고 `예상 주문액`까지 본 다음에야
알 수 있었다.

보간한 값 뒤에 조사를 붙이지 않는다. 끝 글자에 따라 조사가 달라지는데
값은 실행 시점에 정해진다. `49,751원를`, `005930로`가 실제로 그랬다.
종목코드는 특히 위험하다 — `005930`은 `은`이 맞지만 `005932`는 `는`이다.
값은 괄호로 빼거나 문장 끝에 둔다.

    실계좌 매수가능 금액을 초과합니다 (49,751원).
    허용 종목이 좁혀져 있습니다 (005930).
    차단 종목입니다 (005930).

`에`·`의`처럼 받침과 무관한 조사는 붙여도 된다. 라벨이 고정 목록이고 전부
같은 글자로 끝나면(예: `…한도`) 그대로 둬도 되지만, 목록에 항목을 더할 때
확인해야 한다.

0이나 빈 값일 때 문장이 뒤집히지 않는지 본다. `최대 0주까지 매수할 수
있습니다`는 살 수 있다는 말처럼 읽힌다.

같은 말을 쓰는 자리를 한꺼번에 고친다. 주문 화면에는 짝이 있는 자리가 많다 —
매수/매도, 주문 티켓/예약주문 카드. 한쪽만 고치면 두 화면이 어긋난 채로 남는다.
실제로 `최대 0주까지 매수할 수 있습니다`를 고치면서 매도 쪽
`매도가능수량은 0주입니다`를 빠뜨렸고, 주문 티켓에 안내를 올리면서 예약주문
카드는 10px 잔글씨로 뒀다. 문구가 두 곳 이상이면 컴포넌트로 묶는다 —
`UnorderableInstrumentNotice`가 그렇게 나왔다.

버튼의 `disabled`는 화면에 적은 차단 사유와 같은 조건이어야 한다. 예약주문
버튼은 종목 조건만 보고 있어서 지정가가 비어도 눌렸다. 전송 함수가 막아
주긴 했지만, 눌러 봐야 아래 이미 적힌 말을 다시 듣는 셈이었다.

목록을 그리기 전에 `.slice(n)`으로 자르지 않는다. `CollapsibleRows`가 접기를
맡고 있는데 그 앞에서 자르면 `N건 더 보기`를 눌러도 잘린 것은 돌아오지
않는다 — 잔고 16, 주문·체결 30, 매매손익 30, 주문 기록 30, 예약주문 20,
실행 로그 12가 모두 그랬다. 서버가 보낸 것을 그대로 넘기고 접기에 맡긴다.

세는 값에는 특히 상한을 걸지 않는다. `다가오는 일정 N건` 라벨이
`.slice(0, 6)`된 배열을 세고 있어서 8건이 남아도 6건에서 멈췄다. 개수가
개수가 아니게 된다.

헤더의 숫자와 아래 목록이 다른 것을 세고 있지 않은지 본다. 경제 캘린더는
`다가오는 일정 2건`이라고 적고 지난 일정까지 10줄을 같은 모양으로 그렸다.
지난 줄은 `[data-past]`로 눌러 둔다 — 지우지는 않는다.

조회 실패를 빈 값으로 바꾸지 않는다. `.catch(() => setList([]))`로 두면
백엔드가 죽었을 때 화면이 `예약주문이 없습니다` · `실계좌 주문 시도 없음` ·
`아직 체결되지 않은 주문이 없습니다`로 바뀐다. 못 받아온 것과 없는 것은
전혀 다르고, 예약주문은 다음 개장일에 실제로 나가는 주문이라 취소된 것으로
오해하면 손실로 이어진다.

받아 둔 값은 그대로 두고 오류만 올린다.

    .catch((e) => setError(toErrorMessage(e)))

이 규칙은 목록에 특히 중요하다. 단건 값(`매수가능`, `환율`)이 null이 되어
`-`나 `시세 대기`로 보이는 것은 거짓말이 아니다.

다만 그 값이 **기다리는 중**이라고 말하는 자리라면 다르다. null 하나로
`아직 안 옴`과 `못 받음`을 겸하면 실패가 로딩으로 보여 오지 않을 답을
기다리게 된다. 실주문 게이트가 그랬다 — 조회가 깨진 뒤에도 헤더·하단 도크·
주문 패널·차단 사유가 모두 `확인 중`이었다. 실패 사유를 따로 담고, 라벨은
한 곳에서 만들어 네 자리가 같이 쓴다.

    const gateUnknownLabel = liveOrderGateError ? '확인 실패' : '확인 중';

안전 장치의 상태를 모를 때는 막힌 쪽으로 둔다. 게이트를 확인하지 못하면
차단 사유가 남아 주문 버튼은 계속 잠긴다.

주된 동작까지 Tab이 몇 번인지 세어 본다. 마우스로는 바로 누르니 거리가
보이지 않는다. 종목 화면에서 주문 폼까지 46번이었다 — 헤더, 검색, 차트
도구, 지표, 기간, 프리셋을 전부 지나야 오른쪽 패널이 나왔다. 건너뛰기
링크(`.skip-link`)를 두어 5번으로 줄였다.

건너뛰기 링크는 `display: none`으로 숨기지 않는다. 포커스를 못 받아 아예
쓸 수 없게 된다. 화면 밖으로 밀어 두고 포커스가 오면 내린다. 조건은
`:focus-visible`이 아니라 `:focus`를 쓴다 — 화면 밖이라 마우스로는 닿을 수
없으니 모달리티를 따질 이유가 없다.

링크와 대상은 같은 조건에서 렌더한다. 한쪽만 있으면 끊긴 앵커가 된다.

막고 있는 설정을 가리킬 때는 칸 이름을 적고 거기로 데려간다. `아래에서
허용하세요`로는 갈 곳을 찾아야 한다 — 자동매매 차단 사유가 그랬고, 리스크 룰
카드는 534px 아래에 필드가 열 개였다. 이름(`시장가 주문 허용`)을 적고
`설정으로 이동` 버튼으로 스크롤과 포커스를 함께 준다. 포커스만 주면 카드가
화면 밖일 때 보이지 않는 곳으로 커서가 간다.

`scrollIntoView`에 `behavior: 'smooth'`를 붙이지 않는다. 중첩 스크롤
컨테이너(`.chart-panel--portfolio`)에서 아예 움직이지 않았다 — reduced-motion도
CSS scroll-behavior도 기본값인데 그랬다. 즉시 스크롤은 정상 동작한다.

선택지를 동등하게 늘어놓지 않는다. 자동매매 전략 드롭다운이 세 전략을 나란히
보여줬는데, 그중 하나는 8종목 표본에서 확정으로 잃는다. 아는 것이 있으면
선택 전에 밝힌다 — `Strategy.backtestNote`와 `verdict`가 그 자리다.

측정 결과를 화면에 적을 때는 **시점과 조건**을 함께 적는다. `평균 -13.97%`만
적으면 언제 무엇으로 잰 값인지 알 수 없고, 시간이 지나면 조용히 틀린 값이 된다.

    2026-07 측정(8종목·뒤 구간 105봉): 평균 -13.97%, 이익 종목 1/8, 매매 89회.

`<option>`에는 툴팁도 스타일도 붙지 않으므로 판정은 라벨 글에 넣는다
(`변동성 돌파 — 백테스트에서 잃었다`). 자세한 근거는 select 아래 한 줄에 둔다.

> DB(`trading_accounts`) 기반 모의계좌는 주문 화면과 내 계좌 화면에서 걷어냈다.
> 실계좌를 연결해 쓰는데 연습 계좌가 나란히 놓여 어느 계좌로 주문이 나가는지
> 헷갈렸기 때문이다. 지금 `모의`가 남아 있는 곳은 `발견 > 모의투자` 탭 하나뿐이고,
> 이건 서버 없이 localStorage만 쓰는 별도 연습 도구다.

### 재지 않은 숫자

화면 구성을 보려고 넣어 둔 상수를 실제 값처럼 보여주지 않는다. 종목명이
진짜면 그 옆 숫자도 진짜로 읽힌다 — 히트맵이 `삼성전자 +0.22%`를 고정값으로
띄우고 있었고, 리더보드는 사용자의 실제 손익을 지어낸 참가자들과 같은
순위표에 넣고 있었다.

값을 지우면 화면 구성을 못 보므로, 지우는 대신 `<SampleBadge note="…" />`로
밝힌다. `note`에는 **무엇이 예시인지**를 적는다 — "예시입니다"만으로는
어디까지가 실제인지 알 수 없다.

    <SampleBadge note="my-simulation만 내 기록입니다. 나머지 참가자와 손익은 …" />

붙는 자리는 `.terminal-page__header` 또는 `.terminal-panel__header`다.
상태색(초록/노랑)은 쓰지 않는다. 정상/경고 신호가 아니라 "재지 않은 값"이라는
표시라서, 점선 테두리로 구분만 한다.

**같은 개념을 화면과 DB가 서로 다른 값으로 들고 있지 않게 한다.** 테마 보드에
`반도체 = 005930, 000660`이 박혀 있었는데 같은 제품의 DB에는
`반도체/반도체장비 110(101)종목`이 있었다. 한 제품 안에 `반도체 테마`가 둘이면
어느 쪽이 진짜인지 알 수 없다. 화면 구성을 보려고 넣어 둔 것이라도, **진짜
데이터가 생기면 박아 둔 쪽을 지운다.** 지우지 않고 `SampleBadge`만 붙이면
둘이 계속 공존한다.

**낡을 수 있는 명단에는 기준일을 늘 보이게 둔다.** 테마 명단은 매일 받아도
내용은 9개월 전 것이다(2026-07-31에 받은 파일이 2025-11-06자). `지금 반도체
테마`라고 적으면서 그 명단을 보여주면 거짓말이 된다. 등락률은 지금 시세여도
**누구를 그 테마로 볼지는 그날의 판단**이라, 둘을 갈라 적는다.

날짜·기간을 화면 문자열에 박지 않는다. 경제 캘린더 부제가
`KST · 2026년 7월` 고정이라 달이 바뀌어도 7월이라고 적었다. 지금 시각에서
계산한다.

**실계좌로 나가는 자리는 모두 한 번 확인받는다.** 매수·매도만 `주문 확인`
단계가 있었고 예약주문 등록과 정정·취소는 누르는 즉시 전송됐다. 단가를 한
자리 잘못 치고 `확정`을 누르면 그대로 나간다. 확인 단계에는 **무엇이 어떻게
바뀌는지**를 적는다 — 정정은 `250,000원 → 251,000원`, 취소는 `10주 취소`,
예약주문은 종목·수량·단가·계좌·나가는 시점.

**반복되는 결함을 찾을 때, 똑같이 맞추는 게 답이 아닐 수 있다.** 수동 주문과
예약주문에 리스크 룰 사전 검사가 빠져 있어 채웠는데, 정정·취소도 같은 모양으로
비어 있었다. 그런데 여기는 **게이트만 채우고 리스크 룰은 일부러 넣지 않았다** —
서버도 이 경로에서는 `checkRiskRules`를 부르지 않는다. 취소는 위험을 줄이는
동작이라, 룰을 좁힌 뒤 남은 주문을 `허용 종목이 아닙니다`로 막으면 영영 거둘 수
없게 된다. 패턴이 같아 보여도 **서버가 무엇을 검사하는지 먼저 확인한다.**

**주문을 내는 자리가 여럿이면 차단 사유를 한 곳에서 만든다.** 수동 주문 티켓과
예약주문이 각자 따로 검사하다 예약주문 쪽이 리스크 룰과 게이트를 통째로
빠뜨렸다. 서버는 둘 다 검사하는데 화면만 몰라서, 눌러야 거절을 들었다.
`riskRuleBlockers()` 하나를 두 곳이 부른다 — 세 번째 자리가 생겨도 여기만
부르면 된다. 화면은 미리 말해 줄 뿐이고 **판정의 주인은 서버다.** 서버만 아는
것(당일 누적 한도·휴장일·거래 시간)은 흉내 내지 않는다 — 흉내 낸 값이 서버와
어긋나면 그게 더 나쁘다.

**모르는 것을 기본값으로 말하지 않는다.** 자동매매 상태 조회가 실패하면
`autoTrader?.status ?? 'stopped'`가 `멈춤`이라고 적고 시작 버튼까지 켰다.
돌고 있는데 멈춘 것으로 보이고, 또 시작하면 같은 계좌에 두 번 걸린다.
받아 둔 값이 있어도 마지막 조회가 실패했으면 아는 것이 아니다 — 게이트가
쓰는 방식(`확인 중` / `확인 실패` 두 마디)을 그대로 쓰고, 모르는 동안에는
막힌 쪽에 둔다. 성공하면 오류를 지워 일시적 실패는 저절로 낫는다.
502를 흉내 내는 `window.fetch` 가로채기로 재현하고 고쳤다.

새로고침 버튼이 있으면 언제 받아온 값인지도 적는다. 잔고 카드만 `갱신
07:27:39`을 적고 나머지 셋(주문·체결, 주문 기록, 예약주문)과 미체결 주문은
아무것도 적지 않았다. 내용이 같으면 눌러도 화면이 한 픽셀도 바뀌지 않아
눌린 건지 알 수 없다 — 카드 `innerHTML`을 눌러 보기 전후로 비교해 확인했다.
서버가 `updatedAt`을 주면 그것을 쓰고(체결내역), 없으면 받은 시각을 적는다.

**나이는 서버가 준 시각으로 잰다. 응답이 도착한 시각으로 재지 않는다.** 헤더의
`갱신 N초 전`이 `Date.now()`를 찍고 있었는데, 서버는 같은 값을 최대 45초까지 다시
준다 — 2026-07-31 장중 실측에서 45초 묵은 값에 `갱신 3초 전`이 붙어 있었고 그 사이
000660이 −0.81% 움직였다. 값이 시각을 들고 오게 하고(`Quote.fetchedAt`) 화면은
그것만 본다.

목록의 나이는 **가장 묵은 것**으로 말한다. 가장 새 값을 쓰면 한 종목만 방금 와도
목록 전체가 새것으로 보인다. 아무것도 못 받은 회차에는 시각을 건드리지 않는다 —
지금 시각을 찍으면 받은 게 없는데 방금 갱신한 것처럼 보인다.

값이 두 길로 오면 **도착 순서로 덮지 않는다.** 선택 종목 시세는 단건(캐시 없음)으로
방금 오는데 목록 묶음은 45초 캐시라, 조금 뒤에 더 묵은 같은 종목이 도착한다.
시각을 비교해 새 것만 남긴다(`shouldReplaceQuote`).

대체 데이터로 넘어갔으면 화면이 그렇게 말한다. 뉴스룸은 종목 뉴스를 못 찾으면
시장 주제 검색 링크 넷으로 대신하는데, 머리글은 그대로 `자동 큐레이션 · 4건 ·
삼성전자 야간 환산가`였다. 그 종목 뉴스 4건으로 읽힌다 — 실제로는 어느
종목에서든 같은 링크다. 폴백 여부를 값으로 들고(`terminalNewsCards ===
FALLBACK_TERMINAL_NEWS`) 머리글 문구를 함께 바꾼다.

`실시간`은 실제로 스트리밍일 때만 쓴다. 조회해 온 목록이나 검색 링크에
붙이면 지금 오는 것처럼 읽힌다. 뉴스 티커가 그랬는데, `뉴스 ticker`라는
영어를 걷어내면서 내가 붙인 말이었다 — 말을 다듬을 때 없던 주장을 만들지
않도록 본다.

지어낸 콘텐츠에는 짝이 있다. 라운지 게시글에 표시를 붙이고 채팅 메시지는
빠뜨렸었다. 시각이 고정인 것도 단서다 — `실시간 채팅` 아래 08:41이 언제나
최신으로 떠 있었다.

실존하는 회사·상품의 수치를 화면에 적을 때는 어디서 언제 온 값인지 함께
적는다. 수수료 비교표가 그랬다 — 실존 증권사 여덟 곳의 요율이 소수 넷째
자리까지 적혀 있고 1위에 `BEST`까지 붙어 있었는데, 출처도 기준일도 없었다.
초보자가 그걸 보고 계좌를 여는 자리다. 확인된 값이 아니면 그렇다고 밝히고,
추천으로 읽히는 표시(`BEST`)는 범위를 밝히는 말(`이 표에서 최저`)로 바꾼다.

데이터가 없는 항목에 순위·점수를 매기지 않는다. 정렬 키에 `?? 0`을 쓰면 값이
없는 쪽이 전부 0으로 묶여 배열 순서가 그대로 등수가 된다. 값이 있는 것만
순위에 넣고, 나머지는 등수 없이 `CollapsibleRows`로 접어 사유와 함께 둔다.

**판정에는 잰 사실의 이름을 붙인다. 추론한 원인의 이름을 붙이지 않는다.**

그 대응이 12종목 전부 맞았기 때문이다. 그런데 잰 것은 **정규장뿐**이라,
