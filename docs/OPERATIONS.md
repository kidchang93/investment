## 0. 한 장 요약 — 사람이 하는 일은 셋뿐이다

```
아침   zsh scripts/daemon.sh start      ← 이것만 하면 하루가 돈다
장중   슬랙 알림을 본다                   ← 조용하면 정상이다
```

나머지는 데몬이 한다 — 브리핑·판단·주문·손절·감시·마감 정리·일봉 수집.

9일간 안 띄워서 **5거래일이 통째로 빠졌다.** 아침 한 줄이 그 값이다.

## 2. 매일 하는 일

### 2.1 아침 — 한 줄

```bash
cd ~/Desktop/ck/privacy/investment
zsh scripts/daemon.sh start
```

띄우면 이렇게 나온다:

```
데몬을 띄웠다. 상태: zsh scripts/daemon.sh status
```

**터미널을 닫아도 계속 돈다**(`nohup`). 확인은:

```bash
zsh scripts/daemon.sh status
```

```
● 돌고 있다 (pid 13023)
  절전 차단 ● (맥이 자도 계속 돈다)
```

★ **두 줄을 다 봐야 한다.** "돌고 있다"와 "계속 돈다"는 다른 말이다 — 맥이 잠들면
데몬도 함께 멈춘다(`pmset`이 AC 전원에서도 `sleep 1`이다). 데몬이 자기 pid를 물린
`caffeinate`를 띄우므로 보통은 함께 켜지지만, ○로 나오면 `stop` 후 다시 `start`한다.

### 2.2 Docker가 안 떠 있어도 괜찮다

데몬이 Postgres를 기다리다가 **Docker Desktop을 직접 띄운다**(30~60초). 다만
재부팅 직후라면 아침에 이것을 먼저 부르는 쪽이 빠르다:

```bash
zsh scripts/morning.sh    # Docker + Postgres + 백엔드를 한 번에 세운다
```

### 2.3 장중 — 아무것도 안 해도 된다

슬랙만 본다. **조용하면 정상이다.** 경보가 오면 4절을 본다.

지금 무엇을 하고 있는지 궁금하면:

```bash
zsh scripts/status.sh
```

### 2.4 저녁 — 오늘 무엇을 했나

```bash
zsh scripts/status.sh
```

`오늘 자동으로 한 일`에 하트비트가 쌓여 있어야 한다. `premarket`·`deliberate`·
`execute-open`·`close`가 없으면 그 일이 안 된 것이다.

### 2.5 끝낼 때

```bash
zsh scripts/daemon.sh stop
```

**멈추면 멈춘 채로 있는다** — 중지 표식(`.cron-logs/daemon.disabled`)을 남기므로
터미널을 새로 열어도 되살아나지 않는다.

## 3. 명령어 사전

| 명령 | 언제 | 무엇을 하나 | 주문을 내나 |
|---|---|---|---|
| `daemon.sh start` | 아침 | 하루 전체를 자동으로 돌린다 | ○ (판단자 결정을 집행) |
| `daemon.sh status` | 아무 때나 | 돌고 있나 · 오늘 무엇을 했나 | ✗ |
| `daemon.sh stop` | 끝낼 때 | 멈춘다. 자동 기동도 함께 끈다 | ✗ |
| `status.sh` | 아무 때나 | 시스템·계좌·3층·하트비트를 한 화면에 | ✗ |
| `morning.sh` | 재부팅 직후 | Docker·Postgres·백엔드를 세운다 | ✗ |
| `watch.sh` | 궁금할 때 | 지수 + 감시 종목 + 계좌를 한 번에 찍는다 | ✗ |
| `scan.sh` | 궁금할 때 | **오늘 무슨 일이 일어나는지 발견한다**(거래대금 순위·테마) | ✗ |
| `close.sh` | 마감 후 | 종가로 오늘 판단을 채점한다 | ✗ |
| `deliberate.sh` | 손으로 부를 때 | 판단자를 지금 소집한다 (10~15분) | ✗ (기록만) |

백엔드 쪽 스크립트는 `cd backend` 후:

| 명령 | 무엇 |
|---|---|
| `npx tsx src/scripts/layerReport.ts` | 3층 성과 + **장부와 잔고 대조** |
| `npx tsx src/scripts/executeDeliberation.ts VTS-ORDINARY` | 낼 주문을 **미리보기**(`--execute` 없이는 안 나간다) |
| `npx tsx src/scripts/enforceStops.ts VTS-ORDINARY` | 손절선을 깬 자리가 있나 **판정만** |
| `npx tsx src/scripts/layerSync.ts VTS-ORDINARY --apply` | 체결을 층 장부에 넣는다(마감 정리가 자동으로 한다) |
| `npx tsx src/scripts/checkAlerts.ts` | 경보를 지금 확인한다 |

★ **`--execute` / `--apply`가 없으면 아무것도 바꾸지 않는다.** 미리보기가 기본이다.

## 4. 누가 무엇을 사고파나 — 판단과 집행은 갈려 있다

```
판단자 (헤드리스 Claude)          집행기 (규칙)              증권사
  판단만 한다                     주문만 낸다
  ─────────────────              ────────────              ──────
  상태를 모은다        →  decisions에 적는다  →  검사 후 전송  →  KIS
  후보를 훑는다            (지정가·층·계획)       (한도·게이트)
  근거·반증을 적는다
```

**둘을 가른 이유**: 판단자가 직접 주문을 내면 "왜 샀나"를 나중에 되짚을 수 없다.
지금은 회차마다 판단·근거·반증이 DB(`trading_deliberations`)에 남고, 집행기는
그것을 읽어 낼 뿐이다.

### 판단자가 반드시 적어야 하는 것

없으면 기록 자체가 거부된다:

- **`falsifier`** — 결과를 보기 **전에** 적는 반증 조건. "내가 틀렸다면 무엇이 관측되나"
- **매수의 `plan`** — 목표가 · 손절가 · 보유 기간 · 기대수익 · 근거
- **매수의 `limitPrice`·`layer`** — 없으면 시장가로 나가거나 층 장부가 거짓이 된다

### 집행기가 스스로 막는 것

| 막는 것 | 왜 |
|---|---|
| 지정가 없는 주문 | 시장가로 나간다. 슬리피지 실측 0.33% |
| 층 없는 **매수** | 체결을 어느 층으로 되돌릴지 모른다 |
| 어제 판단으로 오늘 주문 | 그 사이 움직인 값을 아무도 안 본 것이 된다 |
| 이미 집행한 결정 | 회차 `executions`와 `clientOrderId`로 두 겹 |

★ **매도의 층은 판단자에게 묻지 않고 장부에서 읽는다**(2026-09-02). 이미 가진
것을 파는 것이라 답이 장부에 있다. 한 종목을 두 층에서 들고 있으면 그때만 막고
판단자가 정하게 한다.

### 손절만은 규칙이 즉시 집행한다

`plan.stopPrice`를 깨면 **판단자를 부르지 않고** 곧바로 시장가로 판다. 판단자를
부르면 1~2분이 걸리고 급락에 그 지연은 치명적이다. 그리고 그 손절값은 **판단자
자신이 사기 전에 적은 값**이라, 규칙이 집행하는 것은 새 판단이 아니라 자기 약속을
지키는 것이다(2026-08-20 사람이 정했다).

## 5. 3층 포트폴리오

| 층 | 목표 비중 | 무엇 | 종목 상한 |
|---|---|---|---|
| **ETF** | 50% | 시장 노출. 알파를 주장하지 않는다(21.4년 실측 연 12.12%) | 없음 — 층이 50%로 제한 |
| **단기** | 30% | 1~2주 보유, +10% 익절 / −5% 손절 | 한 종목 10% |
| **유망주** | 20% | 자유 베팅. 강한 증명을 요구하므로 자주 0원이다 | 한 종목 10% |

★ **레버리지·인버스 ETF는 개별 주식으로 취급해 10% 상한**을 건다. 2배로 움직여
개별 주식보다 위험하므로 "지수 ETF는 안에서 분산돼 있다"는 예외가 성립하지 않는다.

★ **ETF가 목표를 넘긴 상태를 억지로 맞추지 않는다**(2026-08-20). 받을 층이 비어
있어 판 돈이 현금으로 남기 때문이다 — 비중을 맞추는 게 아니라 그만큼을 쉬게 하는
것이 된다. 아래 두 층을 채우면 자연히 내려간다.

**증권사 잔고는 층을 모른다.** 같은 종목을 두 층에서 사면 수량이 합쳐지므로,
층은 우리 장부가 기억하고 **매번 잔고와 대조**한다. 2026-08-14 중복 체결을 잡은
것이 그 대조였다.

## 6. 안전장치 — 무엇이 막히나

### 6.1 지금 주문이 어디로 나가나

```bash
zsh scripts/status.sh   # ── 주문이 어디로 나가나 ──
```

지금은 **`APP_ENV=vts` — 모의 서버**다. 게이트(`KIS_LIVE_ORDER_ENABLED`)가 열려
있어도 **실계좌로 나가지 않는다.** 실전으로 옮기는 것은 사람의 결정이다.

### 6.2 리스크 룰 (계좌 `VTS-ORDINARY` 실제값)

| 항목 | 값 | 뜻 |
|---|---|---|
| 1회 최대 금액 | 13,000,000원 | 한 주문이 이보다 크면 거부 |
| 1회 최대 수량 | 50,000주 | |
| 일일 금액 한도 | 300,000,000원 | 계좌 전체 합산 |
| 일일 건수 한도 | **40건** | 매수·매도를 가리지 않는다 — **매수가 먼저 다 쓰면 그날 못 판다** |
| 주문 가능 시간 | 09:00~15:30 | 밖에서는 전부 거부 |
| 최대 자리 수 | 12 | |
| 최소 보유 | 60분 | 매도만 |
| **중단선** | **76,000,000원** | 총자산이 내려가면 새 매수를 멈춘다 |

### 6.3 장 마감 뒤에는 아무것도 하지 않는다

사람이 정했다(2026-08-20). 시간외 주문은 모의가 거절하고, 예약주문은 **다음
개장에 시가로** 나가 갭 하락에는 오히려 더 나쁜 값에 팔린다.
**밤사이 위험은 자리 크기로만 줄인다.**

보인다 — 그건 정상이고 마감 정리에서 해소된다. **오늘 우리가 낸 주문으로 설명되지
않는 차이만** 경보가 된다(사람이 MTS로 손수 판 것은 여전히 알린다).

## 8. 문제가 생기면

| 증상 | 원인 | 처방 |
|---|---|---|
| 오늘 아무것도 안 돌았다 | 데몬을 안 띄웠다 / 맥이 잤다 | `daemon.sh status` → `start`. **절전 차단 줄도 본다** |
| 판단은 쌓이는데 주문이 안 나간다 | 백엔드가 죽었다 | 데몬이 스스로 띄운다. 안 되면 `/tmp/kis-api.log` |
| `Postgres가 없다` | Docker Desktop이 안 떴다 | 데몬이 직접 띄운다(30~60초). 급하면 `morning.sh` |
| 판단자가 실패한다 | 시간 예산 초과 · claude CLI 없음 | 하트비트를 안 남기므로 **다음 회차가 다시 시도**한다. `.cron-logs/deliberate-*.log` |
| 장부와 잔고가 어긋난다 | 체결이 장부에 안 들어갔다 | `layerSync.ts --apply`. 층을 모르면 `--layer`로 정해 준다 |
| 층을 몰라 못 넣은 체결 | 손으로 낸 주문 · 옛 매매 | `layerSync.ts --layer <etf\|short\|bet> --apply` |
| 데몬이 둘 떴다 | — | 락(`ln`)이 막는다. 로그에 "물러난다"가 남는다 |

로그 자리:

```
.cron-logs/daemon-YYYYMMDD.log       데몬이 한 모든 것
.cron-logs/deliberate-YYYYMMDD.log   판단자 회차
.cron-logs/bars-YYYYMMDD.log         일봉 수집
/tmp/kis-api.log                     백엔드
```

|---|---|---|
| **모의 서버** | 실계좌로 안 나간다 | 실주문 게이트를 여는 것은 사람의 결정 |
| **재부팅하면 멈춘다** | 그날이 통째로 빠진다 | 자동 시작을 사람이 껐다(그날 돌릴지는 그날 정한다) |
| **판단자 도는 동안 손절이 멈춘다** | 하루 최대 45분 | 손절을 별도 프로세스로 떼야 한다 |
| **15:30 이후 아무것도 안 한다** | 밤사이 위험은 자리 크기로만 | 시간외가 막혀 있고 예약주문은 갭에 더 나쁘다 |
| **공매도를 못 한다** | 하락은 1배 인버스 ETF로만 | KIS 오픈API에 공매도 주문이 없다 |
| **판단자가 매 회차 새로 시작한다** | 일관된 규칙이 안 쌓인다 | 그래서 `STRATEGY_DISCIPLINE.md`가 생겼다 |

## 10. 손대면 안 되는 것

| 하지 말 것 | 왜 |
|---|---|
| `.zshrc`에 데몬 자동 시작 걸기 | **두 번 넣었다 뺐다**(8/21·8/25). Claude Code의 Bash 호출마다 새 셸이라, 걸어 두면 **사람이 멈춘 것이 멈춘 채로 있지 않는다** |
| 리스크 룰·실주문 게이트 완화 | 안전장치이지 성능 파라미터가 아니다 |
| 3층 목표 비중·종목 10% 상한 변경 | 사람이 정한 것(`USER_DECISIONS.md`) |
| 비용 상수 변경 | 실측값이다. 유리하게 고치면 **모든 판정이 거짓**이 된다 |
| 판정 문턱(본페로니·홀드아웃) 변경 | 고치면 측정 자체가 무의미해진다 |
| 전략 파라미터를 매일 바꾸기 | **동결 20거래일.** `STRATEGY_DISCIPLINE.md`를 먼저 읽는다 |
