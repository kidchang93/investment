## 0. 한 장 요약 — 띄울 것은 하나다

```
기동      zsh scripts/morning.sh      ← Docker · Postgres · 백엔드 · 화면
제어      http://localhost:4000       ← 「목표」 탭 맨 위에서 켜고 끈다
```

**터미널에서 하는 일은 기동 하나뿐**이고, 그것도 사장님이 말씀하시면 Claude가
합니다. 나머지는 전부 화면에서 합니다.

★ **자동 시작을 걸지 않습니다** (2026-09-02 사용자 결정) — *"백엔드는 자동으로
켜지 말고 내가 기동하라고 할 때만 기동해줘. 항상 claude 키고 켤 거야."*
`.zshrc`·launchd·로그인 항목 어디에도 넣지 않습니다.

★ **띄운다고 자동화가 도는 것은 아닙니다.** 스케줄러 스위치는 화면에 있고,
그 둘은 다른 것입니다 — 섞으면 "서버를 띄우면 매매가 시작되는" 구조가 됩니다.

## 1. 화면에서 무엇을 하나

`http://localhost:4000` → 「목표」 탭 맨 위에 관제 카드가 있습니다.

| 스위치 | 켜면 | 끄면 |
|---|---|---|
| **자동화** | 브리핑·감시·경보·**손절**·마감 정리·수집이 돈다 | **손절도 안 돈다** — 보유가 있으면 켜 둔다 |
| **매매** | 판단자가 새로 사고판다 | 판단자·집행이 멈춘다 (지금 이쪽) |

★ **손절은 매매 스위치에 안 걸립니다.** `plan.stopPrice`는 판단자가 사기 전에
스스로 적은 값이라, 지키는 것은 새 매매가 아니라 약속을 지키는 것입니다.

작업마다 **[지금 실행]** 버튼이 있어 창을 기다리지 않고 돌릴 수 있습니다.
아래 「최근 실행」을 열면 무엇이 성공/실패했는지와 출력이 보입니다.

## 2. 매일 하는 일

### 2.1 아침 — Claude에게 "기동해줘"

```bash
zsh scripts/morning.sh
```

Docker·Postgres·백엔드·화면을 한 번에 세우고, 계좌와 자동화 상태를 찍어 줍니다.
Docker Desktop이 꺼져 있으면 직접 띄웁니다(30~60초).

끝에 이렇게 나옵니다:

```
── 자동화 ──
  자동화 켜짐 · 매매 꺼짐
  켜고 끄는 것은 화면에서: http://localhost:4000  (「목표」 탭 맨 위)
```

★ **자동화 설정은 DB에 저장돼 백엔드를 재시작해도 이어집니다.** 껐다 켰다고
자동화가 조용히 꺼지지 않습니다.

### 2.2 장중 — 아무것도 안 해도 된다

슬랙만 본다. **조용하면 정상이다.** 경보가 오면 7절을 본다.

지금 무엇을 하고 있는지는 **화면 관제 카드**가 보여준다 — 작업마다 창·오늘 했나·
마지막 시각이 있고, 「최근 실행」을 열면 출력까지 나온다.

### 2.3 저녁 — 오늘 무엇을 했나

화면에서 본다. 터미널로 보려면 `zsh scripts/status.sh`.

`premarket`·`close`가 없으면 그 일이 안 된 것이다(매매를 켜 뒀다면
`deliberate`·`execute-open`도).

### 2.4 끝낼 때

**끌 필요가 없다.** 자동화를 잠시 멈추려면 화면에서 스위치를 내린다 —
그 설정은 DB에 저장돼 백엔드를 재시작해도 이어진다.

백엔드 자체를 내리려면 그 프로세스를 멈춘다(`pkill -f "tsx watch"`). 다음에
`morning.sh`로 다시 세운다.

## 4. 누가 무엇을 사고파나 — 판단과 집행은 갈려 있다

```
판단자 (헤드리스 Claude)          집행기 (규칙)              증권사
  판단만 한다                     주문만 낸다
  ─────────────────              ────────────              ──────
  상태를 모은다        →  decisions에 적는다  →  검사 후 전송  →  KIS
  후보를 훑는다            (지정가·층·계획)       (한도·게이트)
  근거·반증을 적는다
```

**둘을 가른 이유**: 판단자가 직접 주문을 내면 "왜 샀나"를 나중에 되짚을 수 없다.
지금은 회차마다 판단·근거·반증이 DB(`trading_deliberations`)에 남고, 집행기는
그것을 읽어 낼 뿐이다.

### 판단자가 반드시 적어야 하는 것

없으면 기록 자체가 거부된다:

- **`falsifier`** — 결과를 보기 **전에** 적는 반증 조건. "내가 틀렸다면 무엇이 관측되나"
- **매수의 `plan`** — 목표가 · 손절가 · 보유 기간 · 기대수익 · 근거
- **매수의 `limitPrice`·`layer`** — 없으면 시장가로 나가거나 층 장부가 거짓이 된다

### 집행기가 스스로 막는 것

| 막는 것 | 왜 |
|---|---|
| 지정가 없는 주문 | 시장가로 나간다. 슬리피지 실측 0.33% |
| 층 없는 **매수** | 체결을 어느 층으로 되돌릴지 모른다 |
| 어제 판단으로 오늘 주문 | 그 사이 움직인 값을 아무도 안 본 것이 된다 |
| 이미 집행한 결정 | 회차 `executions`와 `clientOrderId`로 두 겹 |

★ **매도의 층은 판단자에게 묻지 않고 장부에서 읽는다**(2026-09-02). 이미 가진
것을 파는 것이라 답이 장부에 있다. 한 종목을 두 층에서 들고 있으면 그때만 막고
판단자가 정하게 한다.

### 손절만은 규칙이 즉시 집행한다

`plan.stopPrice`를 깨면 **판단자를 부르지 않고** 곧바로 시장가로 판다. 판단자를
부르면 1~2분이 걸리고 급락에 그 지연은 치명적이다. 그리고 그 손절값은 **판단자
자신이 사기 전에 적은 값**이라, 규칙이 집행하는 것은 새 판단이 아니라 자기 약속을
지키는 것이다(2026-08-20 사람이 정했다).

## 5. 3층 포트폴리오

| 층 | 목표 비중 | 무엇 | 종목 상한 |
|---|---|---|---|
| **ETF** | 50% | 시장 노출. 알파를 주장하지 않는다(21.4년 실측 연 12.12%) | 없음 — 층이 50%로 제한 |
| **단기** | 30% | 1~2주 보유, +10% 익절 / −5% 손절 | 한 종목 10% |
| **유망주** | 20% | 자유 베팅. 강한 증명을 요구하므로 자주 0원이다 | 한 종목 10% |

★ **레버리지·인버스 ETF는 개별 주식으로 취급해 10% 상한**을 건다. 2배로 움직여
개별 주식보다 위험하므로 "지수 ETF는 안에서 분산돼 있다"는 예외가 성립하지 않는다.

★ **ETF가 목표를 넘긴 상태를 억지로 맞추지 않는다**(2026-08-20). 받을 층이 비어
있어 판 돈이 현금으로 남기 때문이다 — 비중을 맞추는 게 아니라 그만큼을 쉬게 하는
것이 된다. 아래 두 층을 채우면 자연히 내려간다.

**증권사 잔고는 층을 모른다.** 같은 종목을 두 층에서 사면 수량이 합쳐지므로,
층은 우리 장부가 기억하고 **매번 잔고와 대조**한다. 2026-08-14 중복 체결을 잡은
것이 그 대조였다.

## 6. 안전장치 — 무엇이 막히나

### 6.1 지금 주문이 어디로 나가나

```bash
zsh scripts/status.sh   # ── 주문이 어디로 나가나 ──
```

지금은 **`APP_ENV=vts` — 모의 서버**다. 게이트(`KIS_LIVE_ORDER_ENABLED`)가 열려
있어도 **실계좌로 나가지 않는다.** 실전으로 옮기는 것은 사람의 결정이다.

### 6.2 리스크 룰 (계좌 `VTS-ORDINARY` 실제값)

| 항목 | 값 | 뜻 |
|---|---|---|
| 1회 최대 금액 | 13,000,000원 | 한 주문이 이보다 크면 거부 |
| 1회 최대 수량 | 50,000주 | |
| 일일 금액 한도 | 300,000,000원 | 계좌 전체 합산 |
| 일일 건수 한도 | **40건** | 매수·매도를 가리지 않는다 — **매수가 먼저 다 쓰면 그날 못 판다** |
| 주문 가능 시간 | 09:00~15:30 | 밖에서는 전부 거부 |
| 최대 자리 수 | 12 | |
| 최소 보유 | 60분 | 매도만 |
| **중단선** | **76,000,000원** | 총자산이 내려가면 새 매수를 멈춘다 |

### 6.3 장 마감 뒤에는 아무것도 하지 않는다

사람이 정했다(2026-08-20). 시간외 주문은 모의가 거절하고, 예약주문은 **다음
개장에 시가로** 나가 갭 하락에는 오히려 더 나쁜 값에 팔린다.
**밤사이 위험은 자리 크기로만 줄인다.**

## 8. 문제가 생기면

| 증상 | 원인 | 처방 |
|---|---|---|
| 화면이 안 열린다 | 백엔드가 안 떴다 | `zsh scripts/morning.sh` |
| 화면은 열리는데 아무것도 안 돈다 | **자동화 스위치가 꺼져 있다** | 화면 관제 카드에서 켠다 |
| 오늘 아무것도 안 돌았다 | 기동을 안 했다 / 맥이 잤다 | `morning.sh`. 자동 시작은 일부러 안 건다 |
| 판단은 쌓이는데 주문이 안 나간다 | **매매 스위치가 꺼져 있다** | 그게 지금 설계다. 켜려면 화면에서 |
| 화면이 빈 페이지다 | `frontend/dist`가 없다 | `npm run build`. `morning.sh`가 없으면 만든다 |
| 판단자가 실패한다 | 시간 예산 초과 · claude CLI 없음 | 하트비트를 안 남기므로 **다음 회차가 다시 시도**한다. `.cron-logs/deliberate-*.log` |
| 장부와 잔고가 어긋난다 | 체결이 장부에 안 들어갔다 | `layerSync.ts --apply`. 층을 모르면 `--layer`로 정해 준다 |
| 층을 몰라 못 넣은 체결 | 손으로 낸 주문 · 옛 매매 | `layerSync.ts --layer <etf\|short\|bet> --apply` |
| 같은 작업이 두 번 돈다 | **`daemon.sh`를 같이 띄웠다** | 그건 이제 안 쓴다. 백엔드 스케줄러 하나만 돌아야 한다 |

로그 자리:

```
.cron-logs/daemon-YYYYMMDD.log       데몬이 한 모든 것
.cron-logs/deliberate-YYYYMMDD.log   판단자 회차
.cron-logs/bars-YYYYMMDD.log         일봉 수집
/tmp/kis-api.log                     백엔드
```

|---|---|---|
| **모의 서버** | 실계좌로 안 나간다 | 실주문 게이트를 여는 것은 사람의 결정 |
| **재부팅하면 멈춘다** | 그날이 통째로 빠진다 | 자동 시작을 안 건다 — 사용자가 늘 Claude를 켜고 시작하므로 그때 말하면 된다(2026-09-02) |
| **판단자 도는 동안 손절이 멈춘다** | 하루 최대 45분 | 손절을 별도 프로세스로 떼야 한다 |
| **15:30 이후 아무것도 안 한다** | 밤사이 위험은 자리 크기로만 | 시간외가 막혀 있고 예약주문은 갭에 더 나쁘다 |
| **공매도를 못 한다** | 하락은 1배 인버스 ETF로만 | KIS 오픈API에 공매도 주문이 없다 |
| **판단자가 매 회차 새로 시작한다** | 일관된 규칙이 안 쌓인다 | 그래서 `STRATEGY_DISCIPLINE.md`가 생겼다 |

## 10. 손대면 안 되는 것

| 하지 말 것 | 왜 |
|---|---|
| **자동 시작 걸기**(`.zshrc`·launchd·로그인 항목) | 세 번 거절된 결정이다(8/21·8/25·9/2). 사용자가 늘 Claude를 켜고 시작하므로 그 자리에서 말하면 된다 |
| `scripts/daemon.sh`를 띄우기 | 2026-09-02부터 안 쓴다. 백엔드 스케줄러와 **둘 다 돌면 같은 작업이 두 번** 나간다 |
| 리스크 룰·실주문 게이트 완화 | 안전장치이지 성능 파라미터가 아니다 |
| 3층 목표 비중·종목 10% 상한 변경 | 사람이 정한 것(`USER_DECISIONS.md`) |
| 비용 상수 변경 | 실측값이다. 유리하게 고치면 **모든 판정이 거짓**이 된다 |
| 판정 문턱(본페로니·홀드아웃) 변경 | 고치면 측정 자체가 무의미해진다 |
| 전략 파라미터를 매일 바꾸기 | **동결 20거래일.** `STRATEGY_DISCIPLINE.md`를 먼저 읽는다 |
