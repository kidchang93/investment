## 0. 먼저 읽는다

`CLAUDE.md`와 `docs/` — 특히 `CODE_STYLE.md`(화면 문구 기준), `USER_FINDINGS.md`
(지금까지의 관찰), `TRADING_API.md`(무엇이 미구현인지). 서브에이전트를 띄울 때
**이 경로들을 프롬프트에 반드시 넣는다.**

## 1. 환경을 확인한다

```bash
lsof -i :4000 -sTCP:LISTEN | wc -l      # 백엔드
lsof -i :55432 -sTCP:LISTEN | wc -l     # Postgres
docker ps --format '{{.Names}} {{.Status}}' | grep kis-postgres
```

죽어 있으면: `open -a Docker` → `docker start kis-postgres` → `npm run dev`
(run_in_background). 브라우저는 `mcp__claude-in-chrome__tabs_context_mcp`로 확인.
**확장이 안 붙으면 사용자만 붙일 수 있다** — 그러면 화면 검증이 필요한 요구사항은
`상태: 시작 전`으로 남기고 코드 수준에서 되는 것만 한다.

## 2. 조사 — 서브에이전트를 병렬로

증권사 한 곳당 하나씩. 브라우저가 필요 없어 병렬이 안전하다.

**검색으로는 기능 세부가 잘 안 나온다.** 아래 순서는 **실제로 해 보고 고친 것이다.**

1. **증권사 공식 도움말 사이트** — 값까지 다 적혀 있어 가장 좋았다.
   키움은 `download.kiwoom.com/hero4_help_new/*.htm`에 자동감시주문 한도(50/50/5),
   유효기간(90일), 감시 시간까지 그대로 있었다. **다만 대부분 HTS 화면 기준이라
   MTS에도 있는지는 따로 확인해야 한다.**
2. **앱스토어 스크린샷 원본** — 공식 자산이고 실제 화면이라 탭 이름·버튼을
   판독할 수 있다. `https://apps.apple.com/kr/app/id<앱ID>`
3. **차단되지 않는 안내 페이지** — 키움은 `kiwoom.com/h/banking/apply/*`가 열렸다
   (알림 서비스 조건이 수치까지 있었다)
4. 뉴스·리뷰 — 기능 이름은 얻지만 동작은 못 얻는다
5. 블로그·커뮤니티 — 마지막. "확인 안 됨"으로 취급

> **앱스토어 릴리스 노트는 한국 증권사에서 안 통한다.** 처음엔 이걸 1순위로
> 적었는데, 키움 영웅문S#은 최신부터 2024년까지 **전부 `일부 기능 개선` 한 줄**
> 이었다(iTunes lookup API로 원문 확인). 무엇이 언제 들어갔는지는 이 경로로
> 못 얻는다.
>
> **증권사 홈페이지 본문이 봇 차단될 수 있다.** kiwoom.com 이용가이드는
> `{"eversafeThreat":true}`로 거부됐다(AhnLab). 차단되면 다른 경로를 찾고,
> 못 찾으면 **"확인 못 함"으로 남겨라.**
>
> **앱 이름이 바뀌었을 수 있다.** 키움 국내 MTS는 지금 `영웅문S#`이고 구
> `영웅문S`는 스토어에서 내려갔다. 이름부터 확인하고 시작해라.
>
> **같은 회사의 다른 앱과 섞지 마라.** `영웅문S 글로벌`에는 VWAP/TWAP/OCO가
> 있지만 그건 해외 앱이다 — 국내 MTS의 근거로 쓰면 안 된다.

각 서브에이전트에게:

> `<증권사>` 앱이 제공하는 기능을 조사해라. **본 것만 적고 추측하지 마라.**
> 기능마다 (1) 이름 (2) 무엇을 하는지 한 줄 (3) 어디서 확인했는지 + URL을 남겨라.
> **출처는 위 순서를 따르라** — 공식 도움말 사이트 → 앱스토어 스크린샷 →
> 안내 페이지 → 뉴스 → 블로그. **릴리스 노트는 기대하지 마라**(한국 증권사는
> 대개 "일부 기능 개선" 한 줄이다). 홈페이지 본문이 봇 차단되면 다른 경로를
> 찾고, 못 찾으면 "확인 못 함"으로 남겨라.
> 앱 이름이 바뀌었을 수 있으니 먼저 확인하고, 같은 회사의 해외 앱과 섞지 마라.
> 확인 못 한 것은 "확인 못 함"이라고 적어라. 레포는 건드리지 마라.
> 참고: `CLAUDE.md`, `docs/TRADING_API.md`

## 3. 비교 — 이건 내가 한다

서브에이전트가 가져온 기능마다 **우리 앱에 있는지 코드·화면으로 확인**한다.
`grep`으로 찾고, 서버가 살아 있으면 API를 두드리고, 화면이 되면 실제로 본다.

**요구사항의 전제를 그대로 믿지 마라.** 지금까지 세 번 틀렸다 —
"첫 화면에 주문·계좌라는 말이 없다"는 이미 있었고 없던 건 `실계좌`였다.
"프론트에 리스크 룰 검사가 빠졌다"는 결함이 아니라 `CODE_STYLE`의 결정이었다.
"오류 배너가 8초 뒤 걷혀서 문제"는 배너가 **아예 안 뜨는** 것이었고, 진짜
문제는 계좌 카드가 `조회하는 중`이라고 말하는 쪽이었다.

**내가 쓴 지침도 틀릴 수 있다.** 이 파일의 출처 우선순위 1번이 처음엔 릴리스
노트였는데, 조사 서브에이전트가 그게 빈 값이라는 걸 잡아 와서 고쳤다.

`우리 앱` 칸을 채울 때 **`우리 앱 근거`에 무엇으로 확인했는지 적는다**
(`App.tsx:1234` / `화면 실측 2026-07-27 19:40` / `API 응답`).

## 4. Notion에 쌓는다

`mcp__notion-work__notion-create-pages`로 위 data source에 행을 만든다.

- 이미 있는 기능은 새로 만들지 말고 `notion-update-page`로 고친다
  (먼저 `notion-search`로 같은 `기능` 이름을 찾는다)
- `우리 앱: 있음`인 것도 적는다 — **"이미 있다"는 것도 조사 결과다.**
  다음에 같은 걸 또 조사하지 않게 한다
- `우선순위`는 **실제 돈·안전에 닿는 것**을 높음으로. 화면 편의는 보통 이하

## 5. 구현 — 서브에이전트에게, 다만 조건을 건다

`우선순위: 높음`이고 `상태: 시작 전`인 것부터. 한 번에 하나씩.

각 구현 서브에이전트 프롬프트에 **아래를 그대로 넣는다**:

> **레포**: `/Users/kidchang/Desktop/ck/privacy/investment`
> **먼저 읽어라**: `CLAUDE.md`, `docs/CODE_STYLE.md`, `docs/REVIEW.md`,
> `docs/ARCHITECTURE.md`
>
> **만들기 전에 지금 무엇을 말하는지 먼저 재라.** 이 레포에서 잡은 결함의
> 대부분이 거기서 나왔다 — 재무 표가 높이 0으로 접혀 있던 것(스크린샷으로는
> 안 보였고 `clientHeight`를 재서 알았다), 순위 API가 파라미터 하나로 정렬이
> 뒤죽박죽이던 것, `days=0`이 어제부터이던 것.
>
> **절대 하지 마라**:
> - 실주문 전송, 자동매매 시작, 최종 전송 버튼 누르기
> - 실주문 게이트 열기(`KIS_LIVE_ORDER_ENABLED`). 작업 끝에 `enabled: false`를 확인해라
> - 리스크 룰 값 바꾸기
> - `localStorage` 비우기
> - 소스를 정규식으로 고치기 — `[^,]`가 줄바꿈까지 먹어 파일 수십 줄을 삼킨 적이 있다.
>   문자열 교체를 쓰고 대상이 실제로 있는지 먼저 확인해라
> - `window.Date`를 통째로 바꾸기 — 페이지가 멈춘다. 소스 상수를 잠깐 옮기고
>   `// TEMP-PROBE`를 달았다가 되돌려라(잔여 0 확인)
>
> **화면 규칙**(`docs/CODE_STYLE.md`):
> 어림값은 점선으로. 빈 성적표를 0%로 채우지 마라. 실패를 빈 값으로 넘기지 마라.
> 모르는 상태는 상태색을 지우지 말고 점선을 더해라. 표본이 전체가 아니면 몇 개를
> 봤는지 밝혀라. 성질이 다른 값은 합치지 마라. 삼항 사슬 대신 `Record`를 써라.
>
> **끝내기 전에**: `npm test` · `npm run typecheck` · `npm run typecheck -w frontend`
> · `npm run build -w frontend`가 전부 통과해야 한다. 화면을 고쳤으면 콘솔을 비우고
> 새로 로드해 오류 0을 확인해라. 검증하느라 바꾼 사용자 상태는 되돌려라.
>
> **확인 못 한 것을 확인한 것처럼 쓰지 마라.** 못 본 것은 "확인 못 함"이라고
> 보고해라 — 그게 결과보다 중요할 때가 있다.

### 결과가 오면 내가 검수한다

**서브에이전트 결과를 그대로 믿지 않는다.** 오늘 매뉴얼 서브에이전트가 코드를
정확히 인용했는데, 그 인용된 코드에 **내 계산 실수가 들어 있었다**(원금 대비
비율을 16으로 안 나눠 29.6%로 적혀 있던 것). 인용이 정확한 것과 값이 맞는 것은
다른 문제다.

검수 항목:
- 실제로 화면이 바뀌었는가(`clientHeight`/`scrollHeight`까지)
- 막히는 쪽과 안 막히는 쪽을 **둘 다** 태웠는가
- 계산한 값을 구성 요소로 검산했는가
- 같은 값이 다른 곳에도 있는데 한 곳만 고치지 않았는가 —
  **다만 각각이 무엇을 위한 값인지 먼저 보고 판단한다.** 똑같이 맞추는 게
  답이 아닐 때가 있다(KRX 시각 셋 중 리스크 룰은 성격이 달라 남겼다)

검수를 통과하면 커밋하고 Notion의 `상태`를 `완료`, `구현 커밋`에 해시를 적는다.

## 이 앱이 일부러 안 하는 것

요구사항으로 올리기 전에 확인한다. **이미 판단이 끝난 것들이다.**

| 없는 것 | 왜 |
|------|------|
| 해외주식 주문 | 국내 파이프라인 완주 후 (TR_ID 체계가 다름) |
| 시간외 주문 | `ORD_DVSN` 코드가 정규장과 달라 미구현 |
| 예약주문 정정 | 취소 후 재등록만 |
| 신용 주문 | 미구현 |
| 프론트의 거래시간·휴장일·일일한도 검사 | **서버만 아는 것은 흉내 내지 않는다**(`CODE_STYLE.md`) |
| 정정·취소에 리스크 룰 적용 | 취소는 위험을 줄이는 동작이라 막으면 안 된다 |
| 목표 수익률 제시·투자 자문 | 하지 않는다 |
