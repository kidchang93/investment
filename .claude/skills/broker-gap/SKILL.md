## 0. ★맨 먼저 — Notion이 개인 계정인지 확인한다★

**무엇보다 먼저 한다.** 조사도 코드도 그 다음이다.

```
mcp__notion-personal__notion-fetch  id: "self"
```

응답의 `self.workspace.name`과 `self.user.email`을 본다.

| 나온 값 | 어떻게 하나 |
|------|------|
| 개인 계정(`lck930721@gmail.com`, 워크스페이스 `창규 이의 Notion`) | 그대로 진행 |

회사 계정이면 **아무것도 쓰지 말고** 이렇게 말한다:

> 이 프로젝트는 개인 것이라 개인 Notion에 쌓아야 합니다.
> **개인 계정을 연결해 주세요** — 인증은 제가 대신 할 수 없습니다.

**연결될 때까지 Notion에 쓰지 않는다.** 그동안 할 수 있는 것(코드 대조, 화면 측정, 조사)은

## 3. Notion에 쌓는다

**0절의 계정 확인을 통과했는지 먼저 본다.**

`mcp__notion-personal__notion-create-pages`로 위 data source에 행을 만든다.

**필드 이름을 추측하지 마라.** 제목 칸은 `제목`이 아니라 **`기능`**이다. 전체:

`기능`(title) · `영역` · `우리 앱` · `우선순위` · `상태` · `본 곳`(multi) ·
`우리 앱 근거` · `확인 방법` · `출처 URL` · `구현 커밋` · `적은 날`(date)

- **영역**: 주문 / 시세·차트 / 계좌·손익 / 자동매매 / 탐색·발견 / 알림 / 기타
- **우리 앱**: 없음 / 일부만 / 있음 / 해당없음
- **우선순위**: 높음 / 보통 / 낮음
- **상태**: 시작 전 / 진행 중 / 완료
- **본 곳**: 토스증권 / 키움 영웅문 / 한국투자 한투 / NH나무 / 미래에셋 M-STOCK / 삼성 mPOP / 기타

확실하지 않으면 `notion-fetch`로 스키마부터 읽어라 — 틀리면 400으로 통째로 거부된다.

### 겪은 함정

- **`적은 날`은 자동이 아니다.** 이관하며 `created_time` → `date`로 바뀌었다(그래야 원본
  날짜가 보존된다). 직접 채워라 —
  `"date:적은 날:start": "2026-07-30T10:00:00Z"`, `"date:적은 날:is_datetime": 1`
- **긴 `content`를 여러 페이지에 한꺼번에 넣으면 JSON이 잘린다.** 나눠 보내라
- **`notion-query-data-sources`(SQL)는 방금 쓴 값을 늦게 반영한다.** 갱신을 확인할 때는
  SQL 말고 **페이지를 직접 `notion-fetch`** 해라. 안 그러면 저장이 안 된 줄 알고 또 쓴다
- 이미 있는 기능은 새로 만들지 말고 `notion-update-page`로 고친다
  (먼저 `notion-search`로 같은 `기능` 이름을 찾는다)

### 무엇을 적나

- **`우리 앱: 있음`인 것도 적는다** — "이미 있다"는 것도 조사 결과다.
  다음에 같은 걸 또 조사하지 않게 한다
- `우선순위`는 **실제 돈·안전에 닿는 것**을 높음으로. 화면 편의는 보통 이하
- 본문에는 **왜 그 우선순위인지, 만들기 전에 정해야 할 것**을 적는다.
  값만 있는 행은 다음에 읽어도 판단이 안 선다
