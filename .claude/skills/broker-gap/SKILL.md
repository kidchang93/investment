## 2. 조사 — 서브에이전트를 병렬로

증권사 한 곳당 하나씩. 브라우저가 필요 없어 병렬이 안전하다.

**검색으로는 기능 세부가 잘 안 나온다.** 아래 순서는 **실제로 해 보고 고친 것이다.**

1. **증권사 공식 도움말 사이트** — 값까지 다 적혀 있어 가장 좋았다.
   키움은 `download.kiwoom.com/hero4_help_new/*.htm`에 자동감시주문 한도(50/50/5),
   유효기간(90일), 감시 시간까지 그대로 있었다. **다만 대부분 HTS 화면 기준이라
   MTS에도 있는지는 따로 확인해야 한다.**
2. **앱스토어 스크린샷 원본** — 공식 자산이고 실제 화면이라 탭 이름·버튼을
   판독할 수 있다. `https://apps.apple.com/kr/app/id<앱ID>`
3. **차단되지 않는 안내 페이지** — 키움은 `kiwoom.com/h/banking/apply/*`가 열렸다
   (알림 서비스 조건이 수치까지 있었다)
4. 뉴스·리뷰 — 기능 이름은 얻지만 동작은 못 얻는다
5. 블로그·커뮤니티 — 마지막. "확인 안 됨"으로 취급

> **앱스토어 릴리스 노트는 한국 증권사에서 안 통한다.** 처음엔 이걸 1순위로
> 적었는데, 키움 영웅문S#은 최신부터 2024년까지 **전부 `일부 기능 개선` 한 줄**
> 이었다(iTunes lookup API로 원문 확인). 무엇이 언제 들어갔는지는 이 경로로
> 못 얻는다.
>
> **증권사 홈페이지 본문이 봇 차단될 수 있다.** kiwoom.com 이용가이드는
> `{"eversafeThreat":true}`로 거부됐다(AhnLab). 차단되면 다른 경로를 찾고,
> 못 찾으면 **"확인 못 함"으로 남겨라.**
>
> **앱 이름이 바뀌었을 수 있다.** 키움 국내 MTS는 지금 `영웅문S#`이고 구
> `영웅문S`는 스토어에서 내려갔다. 이름부터 확인하고 시작해라.
>
> **같은 회사의 다른 앱과 섞지 마라.** `영웅문S 글로벌`에는 VWAP/TWAP/OCO가
> 있지만 그건 해외 앱이다 — 국내 MTS의 근거로 쓰면 안 된다.

각 서브에이전트에게:

> `<증권사>` 앱이 제공하는 기능을 조사해라. **본 것만 적고 추측하지 마라.**
> 기능마다 (1) 이름 (2) 무엇을 하는지 한 줄 (3) 어디서 확인했는지 + URL을 남겨라.
> **출처는 위 순서를 따르라** — 공식 도움말 사이트 → 앱스토어 스크린샷 →
> 안내 페이지 → 뉴스 → 블로그. **릴리스 노트는 기대하지 마라**(한국 증권사는
> 대개 "일부 기능 개선" 한 줄이다). 홈페이지 본문이 봇 차단되면 다른 경로를
> 찾고, 못 찾으면 "확인 못 함"으로 남겨라.
> 앱 이름이 바뀌었을 수 있으니 먼저 확인하고, 같은 회사의 해외 앱과 섞지 마라.
> 확인 못 한 것은 "확인 못 함"이라고 적어라. 레포는 건드리지 마라.
> 참고: `CLAUDE.md`, `docs/TRADING_API.md`

## 3. 비교 — 이건 내가 한다

서브에이전트가 가져온 기능마다 **우리 앱에 있는지 코드·화면으로 확인**한다.
`grep`으로 찾고, 서버가 살아 있으면 API를 두드리고, 화면이 되면 실제로 본다.

**요구사항의 전제를 그대로 믿지 마라.** 지금까지 세 번 틀렸다 —
"첫 화면에 주문·계좌라는 말이 없다"는 이미 있었고 없던 건 `실계좌`였다.
"프론트에 리스크 룰 검사가 빠졌다"는 결함이 아니라 `CODE_STYLE`의 결정이었다.
"오류 배너가 8초 뒤 걷혀서 문제"는 배너가 **아예 안 뜨는** 것이었고, 진짜
문제는 계좌 카드가 `조회하는 중`이라고 말하는 쪽이었다.

**내가 쓴 지침도 틀릴 수 있다.** 이 파일의 출처 우선순위 1번이 처음엔 릴리스
노트였는데, 조사 서브에이전트가 그게 빈 값이라는 걸 잡아 와서 고쳤다.

### ★조사자가 틀리는 가장 흔한 방식 — 출처를 옮겨 적는다★

한투 조사 결과가 *"`06`/`07`을 쓰면 시간외 주문이 풀린다"*고 했다. 코드는 실재
했지만 **그 목록이 있던 곳은 매수가능조회였고 주문 전송이 아니었다.** 같은 보고
안에서 `CNDT_PRIC`이 없다며 짚은 줄(`rest.ts:1182`)도 매수가능조회였다 — 실제
주문 함수는 이미 그 필드를 보내고 있었다.

**인용은 정확한데 출처가 틀린 것**이라 읽으면 그럴듯하다. 그래서 규칙:

> **주장마다 "어느 함수의 어느 필드인지"를 확인한다.** 엔드포인트마다 문서화
> 수준이 다르다. 한 곳의 코드 목록을 다른 곳에 옮겨 적으면 안 된다.

같은 파일에서 `EXCG_ID_DVSN_CD`도 그랬다 — `order_cash`는 `(KRX)` 하나인데
정정·취소만 `KRX/NXT/SOR`다. **정정이 넓다고 신규 주문도 넓지 않다.**

KIS 주장을 검증할 때는 공식 레포를 직접 클론해 읽는 것이 가장 빠르다:
`github.com/koreainvestment/open-trading-api` →
`examples_user/domestic_stock/domestic_stock_functions.py`

`우리 앱` 칸을 채울 때 **`우리 앱 근거`에 무엇으로 확인했는지 적는다**
(`App.tsx:1234` / `화면 실측 2026-07-27 19:40` / `API 응답`).

## 4. Notion에 쌓는다

`mcp__notion-work__notion-create-pages`로 위 data source에 행을 만든다.

**필드 이름을 추측하지 마라.** 제목 칸은 `제목`이 아니라 **`기능`**이다. 전체:
`기능`(title) · `영역` · `우리 앱` · `우선순위` · `상태` · `본 곳`(multi) ·
`우리 앱 근거` · `확인 방법` · `출처 URL` · `구현 커밋`. 확실하지 않으면
`notion-fetch`로 스키마부터 읽어라 — 틀리면 400으로 통째로 거부된다.

**긴 `content`를 여러 페이지에 한꺼번에 넣으면 JSON이 잘린다.** 나눠 보내라.

**`notion-query-data-sources`(SQL)는 방금 쓴 값을 늦게 반영한다.** 갱신을
확인할 때는 SQL 말고 **페이지를 직접 `notion-fetch`** 해라. 안 그러면 저장이
안 된 줄 알고 같은 걸 또 쓰게 된다.

- 이미 있는 기능은 새로 만들지 말고 `notion-update-page`로 고친다
  (먼저 `notion-search`로 같은 `기능` 이름을 찾는다)
- `우리 앱: 있음`인 것도 적는다 — **"이미 있다"는 것도 조사 결과다.**
  다음에 같은 걸 또 조사하지 않게 한다
- `우선순위`는 **실제 돈·안전에 닿는 것**을 높음으로. 화면 편의는 보통 이하

>
> **화면 규칙**(`docs/CODE_STYLE.md`):
> 어림값은 점선으로. 빈 성적표를 0%로 채우지 마라. 실패를 빈 값으로 넘기지 마라.

>
> **확인 못 한 것을 확인한 것처럼 쓰지 마라.** 못 본 것은 "확인 못 함"이라고
> 보고해라 — 그게 결과보다 중요할 때가 있다.

### 결과가 오면 내가 검수한다

**서브에이전트 결과를 그대로 믿지 않는다.** 오늘 매뉴얼 서브에이전트가 코드를
정확히 인용했는데, 그 인용된 코드에 **내 계산 실수가 들어 있었다**(원금 대비
비율을 16으로 안 나눠 29.6%로 적혀 있던 것). 인용이 정확한 것과 값이 맞는 것은
다른 문제다.

검수 항목:
- 실제로 화면이 바뀌었는가(`clientHeight`/`scrollHeight`까지)
- 막히는 쪽과 안 막히는 쪽을 **둘 다** 태웠는가.
  실계좌가 비어 있어(예수금 50,000원·보유 0종목·확정 매도 0건) **값이 있는 쪽을
  화면으로 못 태우는 일이 잦다.** 그럴 땐 `shared`에 함수를 두고 시험으로
  덮어라 — `riskRuleBlockers`·`settledRealized` 선례가 있다
- 계산한 값을 구성 요소로 검산했는가.
  **이걸로 백테스트 버그를 잡았다** — 거래별 손익의 합이 실제 현금 변화보다
  정확히 매수 수수료만큼 컸다
- **새로 넣은 시험이 어떤 조건으로 도는지 봤는가.** 승률 시험이 `NO_COSTS`로
  돌아서, 백테스트와 **같은 커밋에 시험이 있었는데도**(`6a75739`) 비용 계산
  버그를 못 잡았다. 비용·오류처럼 **켜야 드러나는 것은 켜고 재는 시험이 따로
  있어야 한다**
- 같은 값이 다른 곳에도 있는데 한 곳만 고치지 않았는가 —
  **다만 각각이 무엇을 위한 값인지 먼저 보고 판단한다.** 똑같이 맞추는 게
  답이 아닐 때가 있다(KRX 시각 셋 중 리스크 룰은 성격이 달라 남겼다)

검수를 통과하면 커밋하고 Notion의 `상태`를 `완료`, `구현 커밋`에 해시를 적는다.

## 7. 계속 돌린다 — 한 바퀴로 끝나지 않는다

조사 → 비교 → 요구사항 → 구현으로 한 번 가고 마는 게 아니라, **구현이 다음
조사거리를 만들어 내는 고리**로 돌린다. 실제로 그렇게 됐다:

```
타사 조사 → "우린 없네" → 코드 대조 → 조사자 주장이 틀림을 발견
   → 문서 정정 → 화면 실측 → 화면이 거짓말하는 것 발견
   → 고치다 측정기 자체의 버그 발견 → 판정문이 낡음을 알게 됨 → …
```

**가장 값진 것들은 조사 결과가 아니라 그걸 검증하는 도중에 나왔다.** 그러니
"조사할 게 없으면 끝"이 아니다.

### 한 바퀴의 크기

**한 반복에 작은 완결 단위 하나.** 매 반복 `npm test` · `typecheck`(양쪽) ·
`build` 통과 후 커밋한다. 크게 잡으면 검증이 흐려지고, 되돌리기도 어렵다.

### 다음 한 바퀴를 고르는 순서

1. **막혀 있던 것이 풀렸나** — 앞 반복이 남긴 실마리부터. 이게 제일 잘 먹혔다
2. **화면을 재라** — 지금 무엇을 말하고 있는지. 결함은 대개 여기서 나온다
3. **Notion에서 `우선순위: 높음` · `상태: 시작 전`** 하나
4. 아직 안 본 증권사 조사를 새로 띄운다(병렬 가능)
5. 아무것도 없으면 **낡은 값을 찾아라** — 세율·비용·판정문처럼 한번 재고 적어
   둔 숫자는 전제가 바뀌면 조용히 거짓이 된다

### 반복 사이에 반드시 넘길 것

다음 반복의 나는 이번 맥락을 못 본다. 그러니 넘긴다:

- **끝난 것**(커밋 해시와 함께)과 **남은 실마리**
- **빗나간 가설도 적는다** — "보유 0종목의 평가손익은 거짓이 아니다"를 안 적으면
  다음에 또 판다. 확인해서 깨끗했다는 것도 결과다
- **실측값**(추정과 구분해서) · **환경 상태**(서버·DB·탭 ID)
- **내가 지킨 선**(실주문 안 보냄, 게이트 `enabled: false` 매 반복 확인)
- **검증 함정** — 겪은 것만. 안 겪은 걸 미리 적으면 지침이 부풀기만 한다

### 문서·Notion을 같이 갱신한다

구현이 전제를 바꿨으면 **그 자리에서** 고친다. 미루면 다음 반복이 낡은 전제로
시작한다. 실제로 이 파일도 그렇게 낡았었다 — "시간외는 `ORD_DVSN` 코드가
달라서"라고 적어 뒀는데, 나중 조사가 그게 부정확함을 밝혔다.

**이 파일 자체도 갱신 대상이다.** 반복 중에 배운 함정은 여기에 적어야 다음
서브에이전트가 안 밟는다.

### 멈출 때

- 사용자가 멈추라고 할 때
- 더 돌려도 나아지지 않을 때 — **억지로 요구사항을 만들지 않는다.**
  "지금은 고칠 게 없다"가 정직한 결과일 수 있다
- 사람의 판단이 필요한 갈림길에 닿았을 때. 대표적으로 **자동감시주문** —
  KIS 오픈API에 서버측 스탑로스가 없어 직접 폴링해야 하고, 그건 "러너는
  재시작하면 멈춘다"는 의도된 결정과 부딪힌다. **이런 건 물어보고 멈춘다**

## 이 앱이 일부러 안 하는 것

요구사항으로 올리기 전에 확인한다. **이미 판단이 끝난 것들이다.**

| 없는 것 | 왜 |
|------|------|
| 해외주식 주문 | 국내 파이프라인 완주 후 (TR_ID 체계가 다름) |
| 시간외 주문 | 미구현. **다만 사유가 오래 부정확했다** — 아래 참고 |
| 예약주문 정정 | 취소 후 재등록만 |
| 신용 주문 | 미구현 |
| 프론트의 거래시간·휴장일·일일한도 검사 | **서버만 아는 것은 흉내 내지 않는다**(`CODE_STYLE.md`) |
| 정정·취소에 리스크 룰 적용 | 취소는 위험을 줄이는 동작이라 막으면 안 된다 |
| 목표 수익률 제시·투자 자문 | 하지 않는다 |

> **"시간외는 `ORD_DVSN` 코드가 달라서"는 절반만 맞았다.** KIS 공식 레포를 직접
> 읽어 보니 `order_cash`(우리가 쓰는 주문 전송)의 `ord_dvsn`에는 **아무 코드
> 목록도 없다.** `06 장후 시간외`·`07 시간외 단일가`가 나오는 곳은
> **매수가능조회**다. 그 코드로 주문이 나간다는 근거는 아직 없다.
>
> 반대로 **예약주문(`order_resv`)은 `00/01/02/05`를 명시하고 `05`가 장전
> 시간외다.** 우리는 `'00'`으로 고정하고 있다 — 근거를 갖고 열 수 있는 유일한
> 문이다. 자세한 표는 `docs/TRADING_API.md` §7.
