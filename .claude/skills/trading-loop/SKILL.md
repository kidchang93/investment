## 0. 환경을 확인한다

```bash
lsof -i :4000 -sTCP:LISTEN | wc -l      # 백엔드
lsof -i :55432 -sTCP:LISTEN | wc -l     # Postgres
docker ps --format '{{.Names}} {{.Status}}' | grep kis-postgres
```

죽어 있으면: `open -a Docker` → `docker start kis-postgres` → `npm run dev`(백그라운드).
Postgres가 없으면 백엔드가 아예 안 뜬다(`ECONNREFUSED 127.0.0.1:55432`).

브라우저는 `mcp__claude-in-chrome__tabs_context_mcp`로 확인한다. **확장이 안 붙으면 사용자만
붙일 수 있다** — 그러면 화면 검증이 필요한 항목은 `시작 전`으로 남기고 코드 수준에서 되는 것만 한다.

**게이트를 확인한다.** `KIS_LIVE_ORDER_ENABLED` 없이 떠 있는 것이 정상이다.

## 0-1. ★개장일이면 아침 루틴이 먼저다★

## 0-2. ★판단을 러너에 반영하는 법★

**판단만 하고 끝내면 아무 일도 안 일어난다.** 러너는 설정대로 돈다.

| 판단 | 설정 |
|------|------|
| 오늘 이 종목들을 산다 | 리스크 룰 `symbolAllowlist`에 종목코드 |
| **오늘은 새로 사지 않는다** | `maxPositions: 0` — **매수만 멈추고 매도는 계속된다** |
| 회전이 너무 빠르다 | `minHoldMinutes` |
| 자리를 줄인다 | `maxPositions` |

`maxPositions: 0`이 핵심이다. **러너를 통째로 끄면 데드크로스 청산도 같이 멈춰
보유 종목이 아무도 안 보는 채로 남는다.** 전략은 매도 신호를 먼저 만들고 그
뒤에 살 자리를 계산하므로, 0이면 새로 안 사되 청산은 그대로 나간다.

★ **허용목록은 매도를 막지 않는다**(2026-08-04에 고쳤다). 어제 산 종목이 오늘
목록에 없는 것은 정상이고, 그때 매도가 막히면 계좌가 하루 만에 얼어붙는다.

시작은 `POST /api/broker/kis/auto-trader/start`. 설정은 `trading_auto_desired`에
남아 **서버가 죽었다 떠도 스스로 돌아온다.**

## 1. 이번 바퀴를 고른다 — 이 순서로

1. **막혀 있던 것이 풀렸나** — 앞 반복이 남긴 실마리부터. 이게 제일 잘 먹혔다
2. **화면을 재라**(`data-analyst`) — 지금 무엇을 말하고 있는지. 결함은 대개 여기서 나온다
3. **Notion에서 `우선순위: 높음` · `상태: 시작 전`** 하나 (`broker-gap` 스킬의 DB)
4. 아직 안 본 증권사 조사를 새로 띄운다(`market-researcher`, 병렬 가능)
5. 아무것도 없으면 **낡은 값을 찾아라** — 세율·비용·판정문처럼 한번 재고 적어 둔 숫자는
   전제가 바뀌면 조용히 거짓이 된다

## 2. 조사·측정 — 병렬로

**병렬이 안전한 것**: 증권사별 조사(서로 안 겹침), 워크스페이스별 독립 조사
(`shared`/`backend`/`frontend`는 서로 의존하지 않는다), 여러 관점의 읽기 전용 탐색.

**순차로 해야 하는 것**: `shared` 타입 변경 → backend/frontend 반영(계약이 먼저다),
`ServerMessage` 유니언 추가(shared → realtime/server → useStream 순서 의존),
같은 파일 동시 편집(필요하면 `isolation: 'worktree'`).

조사와 측정은 동시에 돌려도 된다 — 하나는 레포 밖을, 하나는 레포 안을 본다.

## 5. ★검수 — 이건 내가 한다★

**서브에이전트 결과를 그대로 믿지 않는다.** 매뉴얼 에이전트가 코드를 정확히 인용했는데,
그 인용된 코드에 **내 계산 실수가 들어 있었다**(원금 대비 비율을 16으로 안 나눠 29.6%로
적혀 있던 것). 인용이 정확한 것과 값이 맞는 것은 다른 문제다.

- 실제로 화면이 바뀌었는가 — `clientHeight`/`scrollHeight`까지
- **막히는 쪽과 안 막히는 쪽을 둘 다 태웠는가.** 실계좌가 비어 있어(예수금 소액·보유 0종목·
  확정 매도 0건) **값이 있는 쪽을 화면으로 못 태우는 일이 잦다.** 그럴 땐 `shared`에 함수를
  두고 시험으로 덮어라 — `riskRuleBlockers`·`settledRealized` 선례
- **계산한 값을 구성 요소로 검산했는가.** 이걸로 백테스트 버그를 잡았다 — 거래별 손익의 합이
  실제 현금 변화보다 정확히 매수 수수료만큼 컸다
- **새로 넣은 시험이 어떤 조건으로 도는가.** 승률 시험이 `NO_COSTS`로 돌아서, 백테스트와
  **같은 커밋에 시험이 있었는데도**(`6a75739`) 비용 버그를 못 잡았다
- 같은 값이 다른 곳에도 있는데 한 곳만 고치지 않았는가 — **다만 각각이 무엇을 위한 값인지
  먼저 보고 판단한다.** 똑같이 맞추는 게 답이 아닐 때가 있다(KRX 시각 셋 중 리스크 룰은
  성격이 달라 남겼다)
- 검증 명령의 **실제 출력**을 봤는가. "통과했다"는 보고만 믿지 않는다

검수를 통과하면 커밋한다.

## 6. 실행 — 선택적, 사용자가 연 뒤에만

대부분의 바퀴는 5번에서 끝난다. 실주문이 필요한 바퀴에서만 `live-trader`를 부른다.

**게이트는 사용자가 연다** — `KIS_LIVE_ORDER_ENABLED=true npm run dev:api`.
내가 열지 않고, `live-trader`도 열지 않는다. 닫혀 있으면 사용자에게 요청하고 멈춘다.

장 마감 후에는 **예약주문(15:40~다음 영업일 07:30)만** 접수된다.
확인용으로 낸 주문은 **반드시 즉시 취소한다.**

다음 반복의 나는 이번 맥락을 못 본다. 그러니 넘긴다:

- **끝난 것**(커밋 해시와 함께)과 **남은 실마리**
- **빗나간 가설도 적는다** — "보유 0종목의 평가손익은 거짓이 아니다"를 안 적으면 다음에 또 판다.
  확인해서 깨끗했다는 것도 결과다
- **실측값**(추정과 구분해서) · **환경 상태**(서버·DB·탭 ID)
- **내가 지킨 선** — 실주문 안 보냄, 게이트 `enabled: false` 매 반복 확인

## 멈출 때

- 사용자가 멈추라고 할 때
- 더 돌려도 나아지지 않을 때 — **억지로 요구사항을 만들지 않는다.**
  "지금은 고칠 게 없다"가 정직한 결과일 수 있다
- 사람의 판단이 필요한 갈림길에 닿았을 때. 대표적으로 **자동감시주문** — KIS 오픈API에
  서버측 스탑로스가 없어 직접 폴링해야 하고, 그건 "러너는 재시작하면 멈춘다"는 의도된 결정과
  부딪힌다. **이런 건 물어보고 멈춘다**

## 이 앱이 일부러 안 하는 것

바퀴를 돌리기 전에 확인한다. **이미 판단이 끝난 것들이다.**

| 없는 것 | 왜 |
|------|------|
| 해외주식 주문 | 국내 파이프라인 완주 후 (TR_ID 체계가 다름) |
| 시간외 주문 | 미구현. 예약주문 `05`(장전 시간외)만 근거를 갖고 열 수 있다 |
| 예약주문 정정 | 취소 후 재등록만 |
| 신용 주문 | 미구현 |
| 프론트의 거래시간·휴장일·일일한도 검사 | **서버만 아는 것은 흉내 내지 않는다**(`CODE_STYLE.md`) |
| 정정·취소에 리스크 룰 적용 | 취소는 위험을 줄이는 동작이라 막으면 안 된다 |
| 목표 수익률 제시·투자 자문 | 하지 않는다 |
